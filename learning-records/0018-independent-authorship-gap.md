# 独立写代码能力与"抄参考"模式

2026-10-24 用户自述：开课以来除 enum 外，没有独立完成过任何代码，总是中途去 copy 参考实现；课程对学 Unity 操作有效，但代码"跳一跳够不着"。

诊断（三方共同责任）：
1. 难度阶梯断档——每课代码是 5–8 个概念的组合（语言 + Unity API + 架构决策），但练习形式只有"读懂 + 抄写 + 接线"，从未有"从空白文件写小单元"的中间台阶。enum 能独立写出恰好证明：单概念 + 形态明确 = 可独立完成。
2. 完整参考实现的副作用——答案永远在手边，卡住 30 秒即可抄，"挣扎"（学习真正发生的地方）被短路。参考实现应出现在尝试之后，而非之前。这是课程设计失误。
3. 近期模式漂移——14b 之后因交付压力助手代写的比例持续上升（工具、素材、热键、16a 参考），练习量趋零。

用户的真实资产：Unity 编辑器操作、场景接线、读代码、定位问题、关卡设计均已达标且在增长；缺口仅在"从空白独立成文"。

**Implications:** 后续课程默认改为"先 blank 后参考"协议；插入纯 C# 匠人块（用游戏域、不碰 Unity API、从空白写、先尝试后给参考）；每 2–3 课安排闭卷 Lab。16a 在匠人块补齐零件（步数账本/传送门配对/行归一化/结算/购买判定）后再实现。
