# 《色彩迷宫》关卡策划协作指南

版本：0.2
适用工程：Unity 6000.6.4f1  
关卡格式：`LevelDefinition`
规则修订：2026-10-24

> 时间有限时先看一页结构速查：[LEVEL_PATTERNS.md](LEVEL_PATTERNS.md)

这份文档写给外部关卡策划。你不需要修改 C# 代码，也不需要重新制作主场景。你的主要交付物是一份可加载的关卡数据、一段设计说明和试玩验证记录。

## 先看这里

1. 每个关卡应能在 2–5 分钟内完成。
2. 每关恰好有一个出口 `E`；至少配置 1 个所需材料，地图中的 `M` 可以多于所需数量。
3. 玩家收集的材料数达到关卡所需数量后才能通过出口。
4. 同一个传送门编号必须成对出现。
5. 不要修改脚本、主场景或全局字体。
6. 侧关卡优先放在 `Assets/Content/Levels/`，不要擅自接入主线关卡链。
7. 商店与金币购买内容仍处于搁置阶段；本阶段只制作关卡本身。
8. 地图由矩形行列形成自然边界，不要求用 `#` 围住最外圈。

## 1. 当前关卡目标

玩家从固定起点出发，收集达到通关阈值所需的材料，并抵达出口：

```text
起点 → 规划路径 → 避开或承受危险 → 收集所需数量的 M → 到达 E
```

关卡的核心不是单纯把路画复杂，而是让玩家权衡：

- 更短的路是否更危险？
- 是否值得绕路恢复氧气？
- 是否要用有限炸弹打开通路？
- 传送门会节省时间还是制造迷路风险？
- 宝箱是否值得冒险去拿？

## 2. 坐标系与地图方向

- X：从左到右增加。
- Y：从下到上增加。
- Inspector 中第一条地图字符串是地图顶部。
- 最后一条字符串是地图底部。
- 玩家固定从 `(1,1)` 出发。
- `(1,1)` 是“左下角向右 1 格、向上 1 格”。

一个 7×7 示例：

```text
y=6  #######
y=5  #.....#
y=4  #.....#
y=3  #..R..#
y=2  #.....#
y=1  #.M.ME#
y=0  #######
     0123456  x
```

该地图的起点是左下角的 `(1,1)`，材料分别在 `(2,1)` 和 `(4,1)`，出口在 `(5,1)`。示例故意放了两份材料；当前示意只要求其中一份通关，多余材料属于合法设计。

所有行必须长度一致。最外圈 `#` 不是必需项：地图矩形本身就是关卡边界，坐标超出任一行的范围时会被当作不可通行区域。使用外圈墙可以让边界更醒目，也可以强化局部隔墙与房间结构，但不应把它当作运行时防越界的前提。

下面这张地图没有外圈墙，但七行七列的范围仍会自动挡住走出地图的移动：

```text
.......
.......
..M....
.......
.......
.....E.
.......
```

## 3. 地图字符

| 字符 | 类型 | 当前规则 |
|---|---|---|
| `.` | 地板 | 可通行，恢复 1 点氧气 |
| `#` | 墙 | 不可通行 |
| `S` | 灰石 | 初始不可通行；可在面向它时消耗 1 个炸弹破坏 |
| `R` | 岩浆 | 可通行；损失 1 生命并恢复 1 氧气 |
| `B` | 水 | 可通行；消耗 1 氧气，氧气为 0 时改扣 1 生命 |
| `C` | 宝箱 | 可通行；打开后获得 3 金币和 1 炸弹 |
| `M` | 材料 | 可通行；拾取后令已收集材料数加 1 |
| `E` | 出口 | 材料数达到关卡所需数量时通关，否则提示继续寻找 |
| `1`–`9` | 传送门 | 同数字两格组成一对，进入后传送至另一格 |

当前初始资源：

```text
生命 3
氧气 3
炸弹 0
材料 0
```

当前关卡初始炸弹为 0。若关卡需要用炸弹破坏灰石，必须先让玩家在无需炸弹即可到达的位置找到宝箱；每个宝箱提供 1 个炸弹。

当前每关必须配置 `Step Limit`。只有成功移动才消耗 1 步：

- 撞墙或被灰石挡住不消耗步数；
- 进入传送门算 1 步；
- 放置炸弹不消耗步数；
- 最后一步完成后仍未通关，则因“步数耗尽”失败。

## 4. 必须满足的关卡规则

### 4.1 起点

- `(1,1)` 不能是墙或灰石。
- 推荐使用 `(1,1) = .`。
- 不要在起点直接放致命岩浆。

### 4.2 地图边界

- 地图由等宽的 `Rows` 构成矩形关卡范围；走出这个范围不会进入空白关卡。
- 外围 `#` 可选，不使用外墙也是一张完整地图。
- 如果省略外围墙，应通过颜色、构图或镜头让玩家仍能直观看出可活动范围。
- 内部隔墙、房间和死路仍可由 `#` 组成。

### 4.3 目标完整

- 每关恰好一个 `E`。
- 关卡数据预留 `requiredMaterials`（通关所需材料数），默认至少为 1。
- 地图中的 `M` 数量必须不少于 `requiredMaterials`。
- 地图中的 `M` 可以多于所需数量；多余材料不是配置错误。
- 材料不能藏在无法到达的位置，也不能让所需数量无法凑齐。
- 出口必须能从至少一条合法路径抵达。

预留规则：多余材料未来可以用于辅助通关，例如解锁机关或交换帮助。当前版本只预留这一设计空间，不实现材料消耗、兑换或机关接口；多余材料目前拾取后只增加计数。

> 过渡期限制：当前运行时仍以“至少持有 1 个材料”判断出口，`LevelValidator` 仍要求材料恰好 1 个，`requiredMaterials` 字段尚未落地。代码迁移完成前，需要 `Validate All` 通过的正式关卡仍应只放 1 个 `M`；多材料关卡可以先设计，但不能标记为已可玩。

### 4.4 传送门成对

- `1` 必须和另一个 `1` 配对。
- `2` 必须和另一个 `2` 配对，以此类推。
- 不要出现 1 个或 3 个相同编号。
- 传送门可以被设计成信息挑战，但不能成为随机惩罚。

### 4.5 可完成性

在玩家正常理解规则的前提下，至少存在一条路径满足：

- 收集到至少 `requiredMaterials` 个材料；
- 生命不会提前降到 0；
- 使用步数不超过 `Step Limit`；
- 需要破坏的灰石数量不超过可获得炸弹；
- 最终可以抵达出口。

不要依赖玩家未掌握、且场景中没有提示的隐藏规则。

## 5. 设计约束

### 尺寸

- 小型：`7×7` 到 `9×9`
- 中型：`11×11` 到 `15×15`
- 大型：`17×17` 到 `21×21`

镜头会自动适配关卡尺寸。不要为了适配镜头而随意缩放场景对象。

### 时长

- 目标是 2–5 分钟。
- 第一次玩允许迷路，但不应出现长时间无反馈的空白探索。
- 如果唯一路线需要反复受伤才能记住，通常过难。

### 步数与评价梯度

每一关都应能产生三种清晰结果：

1. 路线或资源规划失败，无法在步数内通关。
2. 能在步数内通关，但因为危险路径而残血。
3. 找到更安全的路线，在步数内满血通关。

如果所有可行路线都会把生命扣到同一数值，步数限制只会变成计时器，不会形成路线取舍。

### 危险提示

- 岩浆和水应该在视觉上清楚可辨。
- 宝箱应让人看得见，但拿取路径可以承担风险。
- 灰石堵路时，玩家必须有机会获得额外炸弹。

### 传送门公平性

传送门首次触发后，当前工程会记忆该编号的配对颜色。设计时仍应满足：

- 玩家第一次进入前能看出这是一个选择。
- 传送后的位置不是立即死亡区域。
- 传送不会把玩家送入无法返回的软锁。
- 同编号传送门在视觉上应使用相同颜色或图案。

### 软锁检查

重点检查以下情况：

- 用唯一炸弹破坏灰石后，才发现材料在另一条需要用炸弹的路上。
- 进入单向传送区域后，无法再找到出口。
- 材料周围被灰石完全封死，但没有宝箱。
- 需要连续穿过超过当前生命可承受数量的岩浆。
- 关键门只能用商店道具解锁，而商店尚未完成。
- 路线长度超过 `Step Limit`，或规划中漏算绕路步数。

### 炸弹

- 按 `E` 在玩家当前格放置炸弹。
- 当前同时只能存在一个未爆炸的炸弹。
- 放置时立即消耗 1 个炸弹，放置本身不计步。
- 玩家之后每完成一次有效移动，引信减少 1。
- 第三次有效移动结束后爆炸。
- 爆炸只破坏炸弹上下左右四格的灰石。
- 玩家处于炸弹格或上下左右四格之一时损失 1 生命。
- 如果爆炸导致死亡，不会继续拾取材料或触发出口。

## 6. 在 Unity 中创建关卡资产

### 路径

侧关卡放在：

```text
Assets/Content/Levels/
```

文件名建议：

```text
Level_Crystal_01
Level_Forest_02
Level_Clockwork_03
```

不要使用 `Final`、`New`、`Test2` 之类以后无法辨认的名字。

### 创建

1. 在 Project 窗口进入 `Assets/Content/Levels`。
2. 右键选择 `Create → Color Maze → Level Definition`。
3. 使用约定的文件名。
4. 在 Inspector 中设置 `Rows`。
5. 确认每一行长度一致。
6. 设置 `Step Limit`，并用实际路线验证足够完成。
7. 侧关卡把 `Next Level` 留为 `None`。
8. `Completion Dialogue` 写 1–4 句 MAYA 台词。

### 对话要求

- 说话者固定为 MAYA。
- 不解释玩家已经能直接看懂的规则。
- 对白用于回应关卡事件、给下一次探索留下悬念。
- 每句保持短句，避免整段小说式说明。

## 7. 本地试玩方法

贡献者可以只提交 `.asset` 和数据说明，由主项目维护者统一验收。若你熟悉 Unity，可以本地试玩：

1. 打开 `Assets/Scenes/Main.unity`。
2. 选中 `Maze`。
3. 记录 `Level` 当前绑定的资产。
4. 临时把你的关卡拖到 `Level` 字段。
5. 进入 Play。
6. 测试完成后退出 Play，并把 `Level` 恢复为原资产。

不要提交为了测试而修改的 `Main.unity`。如果你的改动只为了本地测试，请在提交前还原。

## 8. 试玩验收

提交前至少完成一次完整试玩：

- [ ] Console 没有红色报错。
- [ ] 地图完整出现在镜头内。
- [ ] 从 `(1,1)` 能正常移动。
- [ ] 地图材料数不少于所需材料数，且材料都能拾取。
- [ ] 每份多余材料的位置和存在原因可以解释，但不强制赋予额外效果。
- [ ] 出口恰好一个。
- [ ] 迁移完成前，正式关卡遵守当前“材料恰好一个”的临时限制。
- [ ] 未达到材料阈值时不会通关；达到阈值后能通关。
- [ ] 每个传送门编号恰好两个。
- [ ] 需要破坏的灰石数量与可获得的炸弹匹配。
- [ ] 推荐路线使用的步数不超过 `Step Limit`。
- [ ] 炸弹放置后恰好在第三次有效移动后爆炸。
- [ ] 站在爆炸十字范围内会损失 1 生命。
- [ ] 通关后 MAYA 对话能显示。
- [ ] 失败后可以重开。

## 9. 提交物

### 使用 Git

只提交关卡资产和设计说明：

```text
Assets/Content/Levels/Level_YourName_01.asset
Assets/Content/Levels/Level_YourName_01.asset.meta
docs/level-submissions/Level_YourName_01.md
```

提交前检查：

```powershell
git status
git diff -- "Assets/Content/Levels/Level_YourName_01.asset"
```

不要把 `Library/`、`Temp/`、`Logs/` 或临时测试场景加入提交。

### 不使用 Git

提交一个压缩包，里面包含：

```text
Level_YourName_01.asset
Level_YourName_01.asset.meta
Level_YourName_01.md
screenshots/
```

如果没有 `.meta` 文件，请同时提交地图文本和 Unity 版本，维护者需要重新导入并生成引用。

## 10. 设计说明模板

每关复制一份：

```text
docs/templates/LEVEL_SUBMISSION.md
```

保存为：

```text
docs/level-submissions/Level_YourName_01.md
```

设计说明至少回答：

- 关卡的一句话主题是什么？
- 预计第一次完成时间是多少？
- 正确路线或推荐路线是什么？
- 玩家会在哪里做取舍？
- 最容易造成软锁的地方是什么？
- 你已经如何验证它能完成？

## 11. 审核标准

维护者会按以下顺序审核：

1. 数据是否合法：尺寸、目标、传送门、起点。
2. 是否可完成：资源和路径是否足够。
3. 是否公平：危险和传送是否有可理解的提示。
4. 是否有设计目的：是否存在真实的路线取舍。
5. 是否符合当前内容范围：是否依赖尚未完成的商店或素材。

审核不要求地图风格与示例完全一致。规则明确、目标清楚、玩家能通过观察做出决定，比“像我一样画”更重要。

## 12. 当前不要做的事

- 不要新增 C# 图纸字符或修改现有规则。
- 不要改 HUD、对话框或主场景。
- 不要删除现有关卡。
- 不要添加来源不明的图片、字体或音频。
- 不要把侧关卡擅自接成主线。
- 不要把商店数值强化当作关卡设计条件。
- 不要为了难度堆满岩浆、灰石和传送门。

## 13. 遇到问题时提供什么

把问题发回维护者时，请附：

- 关卡文件名或地图文本；
- 预期结果；
- 实际结果；
- 相关截图或短视频；
- Console 中第一条红错或黄警告；
- 已尝试过的修改。

这样可以快速区分“地图规则错误”“绑定错误”和“游戏代码问题”。
