色彩迷宫 · 开发实训 / 课程 08

找到材料
才算走出迷宫

现在出口只是一个终点，玩家还不知道自己为什么来这里。今天加入材料、出口和关卡状态：没材料只能得到提示，有材料才算完成。

60–80 分钟 状态机 · 目标 · 关卡流程 产出：完整的过关/失败循环

本课胜利条件

关卡现在有了三种状态

状态进入条件玩家能做什么
Playing关卡开始移动、拾取、使用炸弹、去出口
Completed持有材料并进入出口不能继续移动；按 R 重开
Failed生命归零不能继续移动；按 R 重开

这三件事不要散落在各个脚本里：PlayerStats 负责资源，MazeBootstrapper 负责地块，PlayerGridMover 负责移动，LevelFlowController 负责当前关卡状态。

为什么先做流程，再做正式 UI

先让“进行中 → 完成/失败 → 重开”跑通，UI 只是在观察状态。否则先做漂亮界面，规则一变就要重做。

01

TileType.cs：

LevelDefinition.GetTileType 加入两个分支：

MazeBootstrapper.ColorFor 加入颜色：

MazeBootstrapper.cs
case TileType.Material:
    return new Color(0.20f, 0.95f, 0.75f);
case TileType.Exit:
    return new Color(0.18f, 0.65f, 0.35f);

材料是醒目的青绿色，出口是深绿色；两者都可通行。视觉上要能一眼区分“目标”和“出口”。

02

拾取材料与出口查询

在 MazeBootstrapper 里增加一个和开宝箱类似的方法：

MazeBootstrapper.cs · 材料
public bool TryCollectMaterial(Vector2Int cell)
{
    return TryReplace(
        cell,
        TileType.Material,
        TileType.Floor);
}

材料拾取后变地板，所以不会重复拾取；出口不替换，玩家可以站在出口上继续尝试。现有的 TryReplace 已经处理了“逻辑格子 + 渲染器颜色”的同步。

04

把关卡状态抽成 LevelFlowController

新建 LevelState.cs：

LevelState.cs
public enum LevelState
{
    Playing,
    Completed,
    Failed
}

新建 LevelFlowController.cs。它取代原来的 GameOverController：死亡与完成共用同一个状态机和覆盖层。

LevelFlowController.cs
using UnityEngine;
using UnityEngine.InputSystem;
using UnityEngine.SceneManagement;

public class LevelFlowController : MonoBehaviour
{
    [SerializeField] private PlayerStats playerStats;

    public LevelState State { get; private set; }
        = LevelState.Playing;

    public bool IsPlaying =>
        State == LevelState.Playing;

    private string _hint;
    private float _hintUntil;
    private GUIStyle _titleStyle;
    private GUIStyle _hintStyle;

    private void Start()
    {
        if (playerStats == null)
        {
            Debug.LogError(
                "LevelFlowController: 请指定 PlayerStats。",
                this);
            enabled = false;
            return;
        }

        playerStats.Died += HandlePlayerDied;
    }

    private void OnDestroy()
    {
        if (playerStats != null)
        {
            playerStats.Died -= HandlePlayerDied;
        }
    }

    public void ReachExit(bool hasMaterial)
    {
        if (State != LevelState.Playing)
        {
            return;
        }

        if (hasMaterial)
        {
            State = LevelState.Completed;
            return;
        }

        ShowHint("还需要找到材料。");
    }

    private void ShowHint(string message)
    {
        _hint = message;
        _hintUntil = Time.time + 2f;
    }

    private void HandlePlayerDied()
    {
        State = LevelState.Failed;
    }

    private void Update()
    {
        if (State == LevelState.Playing)
        {
            return;
        }

        Keyboard keyboard = Keyboard.current;

        if (keyboard != null &&
            keyboard.rKey.wasPressedThisFrame)
        {
            SceneManager.LoadScene(
                SceneManager.GetActiveScene().buildIndex);
        }
    }

    private void OnGUI()
    {
        EnsureStyles();

        if (State == LevelState.Playing)
        {
            DrawHint();
            return;
        }

        GUI.depth = -10;
        GUI.color = new Color(0f, 0f, 0f, 0.68f);
        GUI.DrawTexture(
            new Rect(0f, 0f, Screen.width, Screen.height),
            Texture2D.whiteTexture);
        GUI.color = Color.white;

        string title = State == LevelState.Completed
            ? "关卡完成"
            : "生命耗尽";
        string hint = "按 R 重开";

        GUI.Label(
            new Rect(0f, Screen.height * 0.5f - 70f,
                Screen.width, 60f),
            title,
            _titleStyle);
        GUI.Label(
            new Rect(0f, Screen.height * 0.5f + 10f,
                Screen.width, 40f),
            hint,
            _hintStyle);
    }

    private void DrawHint()
    {
        if (string.IsNullOrEmpty(_hint) ||
            Time.time >= _hintUntil)
        {
            return;
        }

        GUI.Box(
            new Rect(Screen.width * 0.5f - 180f,
                Screen.height - 80f, 360f, 52f),
            "");
        GUI.Label(
            new Rect(Screen.width * 0.5f - 160f,
                Screen.height - 68f, 320f, 30f),
            _hint,
            _hintStyle);
    }

    private void EnsureStyles()
    {
        if (_titleStyle != null)
        {
            return;
        }

        _titleStyle = new GUIStyle(GUI.skin.label)
        {
            fontSize = 42,
            alignment = TextAnchor.MiddleCenter,
            fontStyle = FontStyle.Bold
        };
        _titleStyle.normal.textColor = Color.white;

        _hintStyle = new GUIStyle(GUI.skin.label)
        {
            fontSize = 24,
            alignment = TextAnchor.MiddleCenter
        };
        _hintStyle.normal.textColor =
            new Color(1f, 0.85f, 0.45f);
    }
}

然后选中 GameManager，移除原来的 GameOverController，添加 LevelFlowController，把 Player 拖到 Player Stats 字段。

05

让移动脚本接入材料与出口

给 PlayerGridMover 增加 Flow 引用，并在 Start 里检查：

PlayerGridMover.cs · 引用
[SerializeField] private LevelFlowController flow;

if (maze == null || flow == null)
{
    Debug.LogError(
        "PlayerGridMover: 请指定 Maze 和 Flow。",
        this);
    enabled = false;
    return;
}

在 Update 开头阻止已结束的关卡继续移动：

PlayerGridMover.cs · Update
if (!stats.IsAlive || !flow.IsPlaying)
{
    return;
}

在 TryMove 里，处理完传送门和宝箱之后加入材料与出口：

PlayerGridMover.cs · 材料与出口
if (tile == TileType.Material)
{
    if (maze.TryCollectMaterial(currentCell))
    {
        stats.AddMaterial();
        Debug.Log("找到材料。");
    }

    stats.ApplyTile(TileType.Floor);
    return;
}

if (tile == TileType.Exit)
{
    stats.ApplyTile(TileType.Floor);
    flow.ReachExit(stats.HasMaterial);
    return;
}

在 Inspector 里把 PlayerGridMover 的 Flow 字段拖成 GameManager。Flow 为空会直接报错并禁用移动，避免一半功能悄悄失效。

06

测试两条完整路径

使用 Level_FlowTest：

  1. 没材料到出口：从起点向右到 (5,1)，再向上到 (5,5) 出口。预期出现“还需要找到材料”，玩家仍可移动。
  2. 拿材料再出口：按 R 重开，从起点向上到 (1,5)，向右拿到 (2,5) 材料，再向右到 (5,5) 出口。预期显示“关卡完成”，玩家停止移动。
  3. 失败：按 R 重开，踩岩浆把生命降到 0。预期显示“生命耗尽”。
  4. 在完成或失败状态按 R，场景重载，HUD 重置，玩家回到起点。
先移除旧组件

如果 GameManager 上还挂着 GameOverController，它和 LevelFlowController 会各自画覆盖层。选中 GameManager，移除 GameOverController 组件，只保留 LevelFlowController。

检索练习：合上资料再答

先不要往上翻。答错没关系，努力回忆本身就在加固记忆。

1. 没拿材料就进入出口，应该怎样？

出口反馈目标未满足，但玩家还应能继续找材料。

2. 为什么把关卡状态放进 LevelFlowController？

移动、资源和地块各自负责自己的事；胜负与重开由流程控制器统一管理。

3. 材料拾取后为什么要变成地板？

运行时格子变成 Floor 后，再次进入不再满足拾取条件。

4. 关卡完成后靠什么阻止玩家继续移动？

LevelFlowController 状态不再是 Playing，移动脚本提前返回，玩家不能继续操作。

报错急救

现象最可能原因处理
材料是洋红色ColorFor 没加 Material加入青绿色，并确认 M 映射。
材料拾取后不变没有调用 TryCollectMaterial检查 TryMove 的 Material 分支。
拿材料到出口仍提示Flow 没绑定，或 HasMaterial 为 false检查 PlayerStats 的 Materials 与 Flow 引用。
完成后还能移动Update 没检查 flow.IsPlaying在 Update 开头加入状态判断。
出现两层覆盖GameOverController 还在 GameManager 上移除旧组件，只保留 LevelFlowController。
按 R 不重开Main 不在构建场景列表，或 Game 视图没焦点检查 Build Profiles 的 Scene List。
Next Level 不存在本课只做重开，下一关在场景流课先完成本关循环，别提前做持久化。
