Lab 规则

脚本放在哪

放在 Assets/Scripts/Labs/GridMovementLab.cs。在 Unity 的 Project 窗口里新建 Labs 文件夹和脚本，让 Unity 生成 .meta；不要把它塞进正式脚本目录的顶层，也不要改正式的 PlayerGridMover.cs。

关于自动补全

先写方法签名和返回类型，再让 IDE 补全 API。不要为了消掉红波浪线写“占位代码”；补全可以帮你打 wasPressedThisFrame，但不能替你决定为什么返回 Vector3 而不是 Vector2Int。

你要重建的数据流

01

IsWalkable

写出这个方法，接受一个格子坐标，回答“玩家能不能进入”。

签名
public bool IsWalkable(Vector2Int cell)
  • 坐标越界：返回 false。
  • 目标是墙：返回 false。
  • 其他类型：返回 true。
  • 不修改任何状态，不打印日志。
卡住超过 10 分钟？点开提示

先比较 cell.x 与 Width、cell.y 与 Height 的上下界；边界安全后，再向关卡查询格子类型。

02

CellToWorld

写出这个方法，把格子坐标变成玩家应该站的世界位置。

签名
public Vector3 CellToWorld(Vector2Int cell)
  • 格子要居中；7×7 地图的中心格是 (3,3)，世界位置是 (0,0,0)。
  • 如果 Maze 根对象移动或缩放，玩家仍要对齐格子。
  • 不要在每个调用处重复写偏移公式。
卡住超过 10 分钟？点开提示

先算出“相对于 Maze 的局部坐标”，再用 Transform 的 TransformPoint 转成世界坐标。

03

ReadDirection

写出这个方法，读取这一帧的移动意图。

签名
private Vector2Int ReadDirection()
  • W / ↑ → Vector2Int.up；S / ↓ → down；A / ← → left；D / → → right。
  • 没有按键 → Vector2Int.zero。
  • 按住不放时，每次按键只应产生一步；不要用“持续按下”判断。
  • 键盘对象不存在时安全返回 zero，不抛异常。
卡住超过 10 分钟？点开提示

新 Input System 里先拿 Keyboard.current，再看具体按键的“这一帧刚按下”状态；不要用旧版 Input.GetKeyDown。

04

TryMove

写出这个方法，把“想走的方向”变成一次合法的状态更新。

签名
private void TryMove(Vector2Int direction)
  • 先算目标格，不要直接改 currentCell。
  • 目标不可走时直接返回，位置和当前格都不变。
  • 可走时按顺序更新当前格、世界位置，最后应用格子效果。
  • 不要在这里直接写“如果是岩浆就扣血”的规则；规则由 PlayerStats 负责。
卡住超过 10 分钟？点开提示

把方法拆成三步：算目标、验证、提交。最后一行应该是把当前格交给 stats.ApplyTile(...)，而不是自己改生命值。

验收用例

场景输入预期
正常移动从 (1,1) 按 W当前格 (1,2)，玩家在格子中心
撞墙从 (1,1) 按 A 到墙当前格和位置都不变
越界从 (0,0) 继续向左不抛异常，不移动
按住按住 W 一秒只移动一格，松开再按才继续
根对象移动Maze 移到 (5,5) 后移动玩家仍然落在格子中心

自检问题

写完后先回答，再打开参考实现：

  1. 为什么 currentCell 要在验证成功之后才更新？
  2. 如果 wasPressedThisFrame 改成 isPressed，手感会怎样？
  3. index % Width 和 index / Width 分别代表什么？
  4. 如果 CellToWorld 不使用 TransformPoint，Maze 移动后会怎样？
  5. 哪一行是读取输入，哪一行是提交状态？
