把本轮金币、已解锁内容和玩家设置写入 JSON 文件。重点是版本字段、损坏恢复与设置应用，而不是把游戏对象直接序列化。

60–80 分钟 JSON · File I/O · Settings 产出：可恢复的存档与设置

本课胜利条件

存档保存的是数据，不是场景

不要把 GameObject、MonoBehaviour 或运行中的 LevelDefinition 直接写进 JSON。建立一个只包含可持久字段的 DTO：

GameSaveData.cs
using System;

[Serializable]
public class GameSaveData
{
    public int version = SaveService.CurrentVersion;
    public int coins;
    public string[] unlockedContentIds =
        Array.Empty<string>();
    public float masterVolume = 0.8f;
    public bool fullscreen = true;
    public int screenWidth = 1280;
    public int screenHeight = 720;
}

coins 与内容 ID 属于游戏进度；音量与窗口属于玩家设置。它们可以先放在同一个文件里，但字段职责要分清。

01

确定文件位置和版本

使用 Application.persistentDataPath，不要写到 Unity 安装目录或 Assets 目录：

SaveService.cs
public const int CurrentVersion = 1;

public static string SavePath =>
    Path.Combine(
        Application.persistentDataPath,
        "save.json");

public static string BackupPath =>
    Path.Combine(
        Application.persistentDataPath,
        "save.backup.json");

未来字段变化时，读取旧版本并通过迁移补默认值，而不是直接假设旧文件拥有新字段。

02

保存：临时文件 → 替换 → 备份

SaveService.cs
string temp = Path.Combine(
    Application.persistentDataPath,
    "save.tmp");

File.WriteAllText(
    temp,
    JsonUtility.ToJson(data, true));

if (File.Exists(SavePath))
{
    File.Replace(temp, SavePath, BackupPath);
}
else
{
    File.Move(temp, SavePath);
}

直接覆盖存档时，如果程序恰好中断，可能只剩半份 JSON。临时文件完整写入后再替换，风险更小。

03

读取：坏档不能拖垮游戏

读取流程必须是“正式档 → 备份 → 默认数据”，每一层都捕获解析异常：

SaveService.cs · TryLoad
if (TryRead(SavePath, out data))
    return true;

if (TryRead(BackupPath, out data))
{
    LastLoadUsedBackup = true;
    return true;
}

data = null;
return false;

调用方在返回 false 时创建 new GameSaveData()。不要在读取失败时自动覆盖坏文件，先保留现场便于排查。

04

应用音量与窗口设置

SettingsController 保存三个值，并在用户改动时立刻应用：

SettingsController.cs · ApplyCurrentValues
AudioListener.volume =
    Mathf.Clamp01(volumeSlider.value);

Vector2Int resolution =
    _resolutions[resolutionDropdown.value];

Screen.SetResolution(
    resolution.x,
    resolution.y,
    fullscreenToggle.isOn);

从文件初始化 UI 时使用 SetValueWithoutNotify，避免“设置控件值”反而触发一次保存。

05

用一个协调器接起存档与设置

SaveCoordinator 负责加载数据、把设置交给 UI，并在设置变化时保存：

SaveCoordinator.cs
private void Start()
{
    if (!SaveService.TryLoad(out GameSaveData data))
        data = new GameSaveData();

    Data = data;
    settings.Apply(Data);
    settings.Changed += Save;
}

public void Save()
{
    settings.CaptureTo(Data);
    SaveService.Save(Data);
}

接下来由你完成 UI：音量 Slider、全屏 Toggle、分辨率 Dropdown。把 SettingsController 和 SaveCoordinator 挂到常驻 GameManager 上并绑定引用。

06

制作设置面板 UI

最省事的做法是复用现有暂停流程：在 Canvas/GameUI 下新建一个 SettingsPanel，不要改动 PausePanel 的继续和重开逻辑。

  1. 在 GameUI 下新建 UI → Panel，命名 SettingsPanel。Anchor 设为四边拉伸，作为深色遮罩；再在它下面新建一个普通 UI → Panel，命名 SettingsCard，尺寸约 560 × 430、Anchor 和 Pivot 居中。这里的 Card 只是命名习惯，不是 Unity 组件类型。
  2. Card 顶部放标题 TMP“设置”。下面放三行：VolumeRow、FullscreenRow、ResolutionRow。每行左侧放说明文字，右侧放控件。
  3. 音量行：新建 UI → Slider，宽约 300，Min Value 为 0、Max Value 为 1、Value 为 0.8，Whole Numbers 关闭。
  4. 全屏行：新建 UI → Toggle，宽约 300，Is On 先设为 true；保留 Toggle 自带的 Background/Checkmark。
  5. 分辨率行：新建 UI → Dropdown - TextMeshPro，宽约 300；Caption Text 先写“分辨率”。运行时脚本会自动填入分辨率选项。
  6. Card 底部放 CloseButton，文案“返回”。
  7. 在现有 PausePanel 中添加 SettingsButton，文案“设置”，位置可以放在“继续”和“重开”下面。
  8. 把 SettingsController 与 SaveCoordinator 挂在常驻的 GameManager 上，不要挂在默认关闭的 SettingsPanel 上。

最后配置两个点击事件：PausePanel 的 SettingsButton 调用 SettingsController.Open；SettingsPanel 的 CloseButton 调用 SettingsController.Close。设置值变化后会自动应用，并在约 0.25 秒后保存。

不要手工再绑 Slider/Toggle/Dropdown 的 OnValueChanged

SettingsController 已经在代码中订阅这三项变化。Inspector 再绑一次会造成重复应用和重复保存。

07

只做三次快速验收

  1. 修改音量与分辨率，退出 Play 再进入：设置从文件恢复。
  2. 找到 Application.persistentDataPath，把 save.json 改成无效内容：游戏能读取 backup，或不崩溃地回到默认值。
  3. 删除正式档和备份，再进入游戏：使用默认设置，不产生 Console 异常。

边界细节与报错由你调试；遇到具体失败再贴 Console，不需要提前写完所有测试。
