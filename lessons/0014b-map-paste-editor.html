整张地图
一次贴进去

先不画网格。今天只解决最痛的一步：把完整的地图文本一次粘贴进 LevelDefinition，并在写入资产前验证行宽和字符。

30–45 分钟Codec · Custom Inspector产出：批量粘贴地图

本课胜利条件

先实现解析器

在 Assets/Editor/LevelMapCodec.cs 新建 Editor 专用解析器。先确定接口：

LevelMapCodec.cs
public static bool TryNormalize(
    string text,
    out string[] rows,
    out string error)
{
    // 你的实现
}

处理顺序：

  1. 把 \r\n 和 \r 统一成 \n。
  2. 按换行拆开，并去掉每一行首尾空格。
  3. 删除文本最前和最后的空行，但保留中间空行作为错误。
  4. 检查行宽一致。
  5. 只允许 .#SRBCME123456789。
  6. 成功时才给 rows 赋值。
提示

错误信息要包含第几行、第几列。解析器不依赖 Unity 的 Inspector，之后窗口和测试都能复用它。

01

做一个最小测试表

先自己手测这些输入：

输入预期
合法的 7×7 地图通过，行数高度正确
Windows CRLF 文本通过
某行多一个字符指出该行宽度
中间有纯空行拒绝
使用字母 Q指出行列位置
02

写自定义 Inspector

在 Assets/Editor/LevelDefinitionEditor.cs 添加：

[CustomEditor(typeof(LevelDefinition))]
public class LevelDefinitionEditor : Editor

界面包含：多行文本输入、Paste 按钮、状态 HelpBox。不要每次按键都写资产，先把文本留在编辑器中。

点击 Paste 后才通过 SerializedObject.FindProperty("rows") 写入数组。写入前调用 Undo，让 Ctrl+Z 能恢复上一张地图。

常见错误

不要利用换行直接修改 YAML，也不要给私有 rows 增加公开 setter。Editor 可以通过 SerializedObject 正常修改它。

03

接入现有校验

解析成功后先让 LevelMapCodec 通过，再写入资产；写入后调用 LevelValidator.Validate(level)，把错误显示在 Inspector 中，不要只丢进 Console。

04

验收

  1. 打开任意关卡，整张地图只需粘贴一次。
  2. 粘贴坏行宽地图，资产内容保持不变。
  3. 成功粘贴后按 Ctrl+Z，地图恢复上一版。
  4. 停止 Play、重新进入 Unity 后，地图仍然保留。

卡住时先告诉我失败的是解析、SerializedProperty 写入还是 Undo。现在不要提前做网格画笔。
