色彩迷宫 · 开发实训 / 课程 11

让每次操作
都有回音

拾取材料、踩进岩浆、炸开石头，本来会分别调用音效。今天建立一个统一的反馈入口：同一个动作同时触发声音与短暂画面提示，而调用方不必知道每种反馈怎样实现。

50–70 分钟 Facade · Coroutine · UI Image 产出：受击与拾取反馈

本课胜利条件

反馈不是一把音效开关

“踩到岩浆”和“拾取材料”是两个游戏事件。声音、颜色和时长只是它们当前选择的表达方式。调用方应该说“玩家受伤了”，而不是同时知道要播哪个 Clip、打开哪张图片、等待多少秒。

点击一次查看反馈

真正的游戏会同时播放声音；这里先观察颜色、方向和时长如何把两个事件区分开。

CALLER

只说发生了什么

feedback.Damage() 比一串底层播放调用更能表达意图。

FACADE

组合多种反馈

一个入口内部协调声音与画面，调用方不需要知道组合细节。

ACCESS

不只依赖颜色

颜色只是附加提示；音效、HUD 数字和明确文字仍然表达结果。

01

先盘点现有反馈入口

打开 PlayerGridMover.cs，目前与反馈有关的调用分散在移动、炸弹和传送分支里：

事件现在直接调用目标语义
踩岩浆audio.PlayDamage()feedback.Damage()
拿材料audio.PlayPickup()feedback.Pickup()
开宝箱audio.PlayChestOpen()feedback.ChestOpened()
炸石头audio.PlayStoneBreak()feedback.StoneBroken()
使用传送门audio.PlayPortal()feedback.PortalUsed()
无效操作audio.PlayUiError()feedback.Error()

这一步先不改行为，只把“事件名称”和“播放名称”分开。

02

建立 GameFeedback 入口

在 Assets/Scripts 新建 GameFeedback.cs。它依赖低层 AudioManager 和一张 UI 遮罩：

GameFeedback.cs · 字段
[SerializeField] private AudioManager audio;
[SerializeField] private Image screenFlash;

[SerializeField] private Color damageColor =
    new Color(0.75f, 0.12f, 0.10f, 0.22f);
[SerializeField] private Color gainColor =
    new Color(1f, 0.78f, 0.18f, 0.12f);

private Coroutine _flashRoutine;

对外方法只描述游戏事件：

GameFeedback.cs · 事件入口
public void Damage()
{
    audio.PlayDamage();
    Flash(damageColor, 0.2f);
}

public void Pickup()
{
    audio.PlayPickup();
    Flash(gainColor, 0.12f);
}

完整入口还包含 ChestOpened、StoneBroken、PortalUsed 和 Error。参考：GameFeedback.cs。

03

让闪光自行淡出

每次反馈只保存一个 Coroutine 引用。新事件到来时，先停止旧动画，再启动新动画，避免两个 alpha 同时写同一张图片：

GameFeedback.cs · FlashRoutine
while (elapsed < duration)
{
    elapsed += Time.unscaledDeltaTime;
    float progress =
        Mathf.Clamp01(elapsed / duration);

    screenFlash.color = new Color(
        color.r,
        color.g,
        color.b,
        Mathf.Lerp(color.a, 0f, progress));

    yield return null;
}

ClearFlash();

受击闪光的持续时间应短于 0.25 秒。画面提示是补充，不应该拖慢玩家再次操作。

04

把 PlayerGridMover 改为依赖语义

把字段从 AudioManager 改为 GameFeedback，并逐一替换调用：

PlayerGridMover.cs
// 字段
[SerializeField] private GameFeedback feedback;

// 示例
stats.AddMaterial();
feedback.Pickup();

// 受击
if (tile == TileType.Lava && stats.IsAlive)
{
    feedback.Damage();
}

Start 的引用检查也要改成 feedback == null。完整参考：PlayerGridMover.cs。

职责没有消失，只是移动了

AudioManager 仍然负责播放 Clip；GameFeedback 负责“哪个游戏事件应该产生哪些反馈”。这是外观层 Facade，不是把音频系统删掉。

05

创建不挡操作的遮罩

在 Canvas 下新建一个全屏 Image，命名为 FeedbackFlash：

属性设置
RectTransformAnchor 四边拉伸，Left/Top/Right/Bottom 均为 0
Color任意反馈色，Alpha 设为 0
Raycast Target关闭；也可由 Awake 再强制关闭
层级覆盖游戏画面，但放在 HUD 与结算面板下方

在 GameManager 上添加 GameFeedback，绑定 Audio 与 FeedbackFlash；再把 PlayerGridMover 的 Feedback 字段指向它。

不要让反馈阻止输入

Image 默认会成为 UI Raycast Target。全屏遮罩如果开启，会吞掉鼠标点击，使对话推进和按钮变得不稳定。

06

测试组合反馈与边界

  1. 拾取材料：听到拾取音效，并看到很短的暖色闪光。
  2. 踩进岩浆但未死亡：听到伤害音效，并看到红色闪光。
  3. 炸开石头、打开宝箱、使用传送门：各自触发对应声音和颜色。
  4. 快速连续触发两种反馈：画面不应残留上一层颜色。
  5. 反馈播放时点击对话框或按钮：输入仍然有效。
  6. 暂停游戏后触发错误提示：若反馈由 UI 触发，动画也不应依赖 timeScale。
可访问性检查

把音量调到很低时，HUD 仍然显示生命、氧气和材料变化；不要用“闪红”代替受伤文字或数值。对强闪光敏感的用户，应能通过取消 screenFlash 引用关闭画面闪光而保留声音。

检索练习

先不要往上翻。

1. 为什么 PlayerGridMover 调用 GameFeedback？

调用方表达“受伤/拾取”，具体声音和画面组合留在反馈层。

2. 新反馈开始时为什么先停止旧 Coroutine？

两个协程同时写同一张 Image，会出现闪烁或残留 alpha。

3. 为什么全屏反馈遮罩要关闭 Raycast Target？

反馈层只负责显示，不能参与界面命中测试。

4. 反馈闪光为什么使用 unscaledDeltaTime？

UI 反馈的显示时间不应绑定游戏世界的时间缩放。

报错急救

现象处理
有声音但没闪光GameFeedback 的 Screen Flash 是否绑定，Image Alpha 是否为 0 起始。
画面一直发红协程是否在结束后调用 ClearFlash，duration 是否大于 0。
反馈后不能点按钮FeedbackFlash 的 Raycast Target 是否仍开启。
连点时颜色乱跳启动新动画前是否 StopCoroutine 旧协程。
受击音效播放两次检查死亡路径：HUD 与 LevelFlowController 是否都在播放。
暂停时闪光冻结动画时间是否误用了 Time.deltaTime。
