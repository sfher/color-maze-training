45–60 分钟ScriptableObject · SpriteRenderer产出：像素版主循环

本课胜利条件

先想清楚：什么变了，什么没变

渲染管线对比
现在  字符 → CreateSquareSprite() 1×1 白块 → color = ColorFor(tile)
目标  字符 → TileVisuals.GetSprite(tile)  → 像素地砖
                └ Portal 例外：白色螺旋 × PortalColor(id) 染色

现在的白块是“全白 + 乘色”，所以 ColorFor 能当调色盘用。换成像素地砖后，地砖自带颜色，color 只剩一个职责：给白色螺旋染传送门色。记住这句话，下面每一处改动都是在执行它。

本课只动两个脚本和两处场景，关卡数据、移动、规则、相机、HUD 一概不动。

01

新建 TileVisuals（完整代码）

新建 Assets/Scripts/TileVisuals.cs（运行时程序集，不是 Editor），整个文件如下：

TileVisuals.cs · 完整
using UnityEngine;

/// <summary>
/// 一套关卡视觉皮肤：每种 TileType 对应一张像素地砖。
/// 换主题 = 换一张 TileVisuals 资产，渲染代码不变。
/// </summary>
[CreateAssetMenu(
    menuName = "Color Maze/Tile Visuals",
    fileName = "TileVisuals_Classic")]
public class TileVisuals : ScriptableObject
{
    [SerializeField] private Sprite floor;
    [SerializeField] private Sprite wall;
    [SerializeField] private Sprite stone;
    [SerializeField] private Sprite water;
    [SerializeField] private Sprite lava;
    [SerializeField] private Sprite chest;
    [SerializeField] private Sprite material;
    [SerializeField] private Sprite exit;
    [SerializeField] private Sprite portalBase;

    public Sprite GetSprite(TileType tile)
    {
        switch (tile)
        {
            case TileType.Wall: return wall;
            case TileType.Stone: return stone;
            case TileType.Lava: return lava;
            case TileType.Water: return water;
            case TileType.Chest: return chest;
            case TileType.Portal: return portalBase;
            case TileType.Material: return material;
            case TileType.Exit: return exit;
            default: return floor;
        }
    }
}

逐段理解：

  • [CreateAssetMenu]：让 Project 右键菜单出现 Create → Color Maze → Tile Visuals，和 LevelDefinition 同款做法。
  • 九个字段对应九种地砖：floor/wall/stone/water/lava/chest/material/exit/portalBase。都是 [SerializeField] private，外部只读不写。
  • GetSprite 用 switch 做映射，default 返回 floor——宁可给错地板，也不要返回 null 让渲染器空白。

然后创建资产并填图：Project 进入 Assets/Data/ → 右键 Create → Color Maze → Tile Visuals（名字就用默认 TileVisuals_Classic）→ 按下表拖入 15a 的素材：

字段拖入的素材
floor / wall / water / materialArt/Kenney/RoguelikeCavesDungeons/ 对应 png
chest / exitArt/Kenney/RoguelikeRpg/ 对应 png
lava / stoneArt/Tiles/tile_lava.png、tile_stone.png
portalBaseArt/Tiles/tile_portal.png（白色螺旋）
为什么是 ScriptableObject

商店主题就是“第二张 TileVisuals 资产”：再建一张、拖另一套图、Maze 换引用，零代码换皮。内容进数据、代码只管规则——和 LevelDefinition 是同一个模式。

02

改造 MazeBootstrapper（四处改动 + 一处删除）

完整改造后的文件在 solutions/0019/MazeBootstrapper.cs（已用 Unity 程序集编译验证 0 警告 0 错误）。下面按改动点逐个讲，未提到的部分一行都不用动。

改动 1 · 加一个字段

[SerializeField] private LevelDefinition level;
[SerializeField] private TileVisuals visuals;   // ← 新增

改动 2 · Start 里补判空

在 level 判空之后照抄一段。缺资产时立刻报错停用，比画了半张地图才 NullReference 强得多：

if (visuals == null)
{
    Debug.LogError(
        "MazeBootstrapper: 请在 Inspector 里指定 Tile Visuals。",
        this);
    enabled = false;
    return;
}

改动 3 · CreateCell：白块 → 像素地砖

方法签名里不再需要 Sprite square 参数，删掉它；两行赋值换掉：

private SpriteRenderer CreateCell(
    int x,
    int y,
    TileType tile)
{
    GameObject cell = new GameObject($"Cell_{x}_{y}");
    cell.transform.SetParent(transform);
    cell.transform.localPosition = CellToLocal(new Vector2Int(x, y));

    SpriteRenderer spriteRenderer = cell.AddComponent();
    spriteRenderer.sprite = visuals.GetSprite(tile);
    spriteRenderer.color = Color.white;          // ← 像素地砖自带颜色，tint 归白
    return spriteRenderer;
}

Start 循环里的调用相应改成 CreateCell(x, y, tile)。循环末尾那段 if (tile == TileType.Portal) { ... PortalColor(portalId) } 原样保留——白螺旋乘紫色就是紫螺旋，“踩过后变亮”的记忆机制（MarkPortalPairKnown）只改 color，也自动继续工作。

改动 4 · TryReplace：本课的核心坑

炸石、开箱、捡材料都走这里。旧版只改颜色；新版要换 sprite，并且必须把 color 重置回白：

private bool TryReplace(
    Vector2Int cell,
    TileType expected,
    TileType replacement)
{
    if (GetTileType(cell) != expected)
    {
        return false;
    }

    _tiles[cell.x, cell.y] = replacement;
    _renderers[cell.x, cell.y].sprite =
        visuals.GetSprite(replacement);
    // color 是乘法 tint：换新地砖后必须归白，
    // 否则地板会带上石头灰、水蓝等旧颜色。
    _renderers[cell.x, cell.y].color = Color.white;
    return true;
}

为什么必须归白：SpriteRenderer.color 会乘在贴图每个像素上。石头格原来 tint 着灰色，只换 sprite 的话，新地板贴图 × 灰 = 灰扑扑的地板。这就是“color 只剩传送门一个职责”的另一半：所有非传送门路径离开时都要是白色。

注意

TryBreakStone / TryOpenChest / TryCollectMaterial 保持 public bool 并 return TryReplace(...)——PlayerGridMover 依赖这些返回值，抄参考实现时别把 return 丢了。

删除 · ColorFor

整个 ColorFor(TileType tile) 方法删除（已无调用者）。保留 CreateSquareSprite() 和 _squareSprite——炸弹标记 CreateBombMarker 还在用白方块（缩小 0.5 + 染色，临时标记反而清晰），也保留 PortalColor。

03

场景接线（两处）

  1. Maze 对象：Inspector 里把 TileVisuals_Classic 拖进新字段 Visuals。
  2. Player 对象：SpriteRenderer 的 Sprite 从内置 Square 换成 player_default；Color 从黄 (1, 0.9, 0) 改回纯白——乘法 tint 同理会染黄冒险者；Order in Layer 保持 10（地砖 0、炸弹 5、玩家 10 的层级表已经是对的）。
