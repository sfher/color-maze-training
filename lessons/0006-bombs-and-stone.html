让关卡可以
被改变

灰色石头挡路，炸弹是第一种能改变地图的资源。今天加石头、炸弹和一份运行时地图副本，让“炸开一条路”真正发生。

60–75 分钟 枚举 · 二维数组 · 运行时状态 产出：可炸开的石头
规则已更新

2026-10-22 起，炸弹改为按 E 在脚下放置、三次有效移动后十字爆炸。本文保留历史步骤；当前设计规范以 Color Maze/docs/LEVEL_DESIGN_GUIDE.md 为准。

本课胜利条件

为什么不能直接改 LevelDefinition

最直接的做法是：炸石头时把 LevelDefinition 里的 S 改成 .。但这会带来一个严重问题：ScriptableObject 是磁盘上的资产，编辑器里运行时修改它，停止 Play 后改动可能仍然保留，下一局石头就永远消失了。

资产是模板，不是运行时状态

LevelDefinition 保存“关卡本来长什么样”；MazeBootstrapper 保存“这一局现在长什么样”。炸石头改的是后者。

Template

LevelDefinition

只读的关卡模板。里面有多少石头、水、岩浆，由内容决定。

Runtime

MazeBootstrapper

Start 时复制一份 TileType[,]，这一局的破坏只改副本。

Input

PlayerGridMover

记住面朝方向，按 E 把前方石头交给 Maze 处理。

02

让 Maze 保存运行时副本

用下面的版本替换 MazeBootstrapper.cs。关键变化是：Start 时把关卡复制到 _tiles，同时保存每个格子的 SpriteRenderer，这样炸石头时可以同时改数据和画面。

MazeBootstrapper.cs
using UnityEngine;

public class MazeBootstrapper : MonoBehaviour
{
    [SerializeField] private LevelDefinition level;

    private TileType[,] _tiles;
    private SpriteRenderer[,] _renderers;

    private int Width => level != null ? level.Width : 0;
    private int Height => level != null ? level.Height : 0;

    private void Start()
    {
        if (level == null)
        {
            Debug.LogError(
                "MazeBootstrapper: 请在 Inspector 里指定 Level Definition。",
                this);
            enabled = false;
            return;
        }

        _tiles = new TileType[Width, Height];
        _renderers = new SpriteRenderer[Width, Height];

        Sprite square = CreateSquareSprite();

        for (int y = 0; y < Height; y++)
        {
            for (int x = 0; x < Width; x++)
            {
                TileType tile = level.GetTileType(new Vector2Int(x, y));
                _tiles[x, y] = tile;
                _renderers[x, y] = CreateCell(square, x, y, tile);
            }
        }
    }

    public bool IsWalkable(Vector2Int cell)
    {
        TileType tile = GetTileType(cell);
        return tile != TileType.Wall && tile != TileType.Stone;
    }

    public TileType GetTileType(Vector2Int cell)
    {
        if (level == null || _tiles == null || !level.Contains(cell))
        {
            return TileType.Wall;
        }

        return _tiles[cell.x, cell.y];
    }

    public bool TryBreakStone(Vector2Int cell)
    {
        if (GetTileType(cell) != TileType.Stone)
        {
            return false;
        }

        _tiles[cell.x, cell.y] = TileType.Floor;
        _renderers[cell.x, cell.y].color = ColorFor(TileType.Floor);
        return true;
    }

    public Vector3 CellToWorld(Vector2Int cell)
    {
        return transform.TransformPoint(CellToLocal(cell));
    }

    private Vector3 CellToLocal(Vector2Int cell)
    {
        return new Vector3(
            cell.x - (Width - 1) * 0.5f,
            cell.y - (Height - 1) * 0.5f,
            0f);
    }

    private SpriteRenderer CreateCell(
        Sprite square,
        int x,
        int y,
        TileType tile)
    {
        GameObject cell = new GameObject($"Cell_{x}_{y}");
        cell.transform.SetParent(transform);
        cell.transform.localPosition = CellToLocal(new Vector2Int(x, y));

        SpriteRenderer spriteRenderer = cell.AddComponent<SpriteRenderer>();
        spriteRenderer.sprite = square;
        spriteRenderer.color = ColorFor(tile);
        return spriteRenderer;
    }

    private Color ColorFor(TileType tile)
    {
        switch (tile)
        {
            case TileType.Wall: return new Color(0.10f, 0.10f, 0.12f);
            case TileType.Floor: return new Color(0.93f, 0.92f, 0.88f);
            case TileType.Lava: return new Color(0.82f, 0.22f, 0.20f);
            case TileType.Water: return new Color(0.16f, 0.45f, 0.86f);
            case TileType.Stone: return new Color(0.45f, 0.45f, 0.48f);
            default: return Color.magenta;
        }
    }

    private Sprite CreateSquareSprite()
    {
        Texture2D texture = new Texture2D(1, 1);
        texture.SetPixel(0, 0, Color.white);
        texture.Apply();

        return Sprite.Create(
            texture,
            new Rect(0f, 0f, 1f, 1f),
            new Vector2(0.5f, 0.5f),
            1f);
    }
}

TileType[,] 是二维数组，第一维 x、第二维 y。它和关卡资产分离，所以炸石头只影响这一局；停止 Play 再开，石头会按模板重新出现。

03

给 PlayerStats 和 HUD 加炸弹

在 PlayerStats.cs 的氧气属性下面加入：

PlayerStats.cs · 炸弹状态
public int Bombs { get; private set; } = 1;

public bool TryConsumeBomb()
{
    if (Bombs <= 0)
    {
        return false;
    }

    Bombs -= 1;
    Debug.Log($"炸弹 -1，剩余 {Bombs}");
    return true;
}

把 HUD 的盒子高度从 96 改成 132，并加一行：

PlayerStats.cs · HUD
GUI.Box(new Rect(12f, 12f, 260f, 132f), "");

// 在氧气标签后面加：
GUI.Label(
    new Rect(24f, 94f, 236f, 30f),
    $"炸弹: {Bombs}",
    _labelStyle);

炸弹是资源，所以“数量”归 PlayerStats 管；Maze 只负责“这里有没有石头”，两者不要混在一起。

04

让玩家记住朝向并放炸弹

在 PlayerGridMover.cs 加入朝向、炸弹输入和炸石头逻辑。改动如下：

PlayerGridMover.cs · 改动清单
// 字段
private Vector2Int facing = Vector2Int.up;

// Update 开头，读取方向之前
if (ReadBombPressed())
{
    TryUseBomb();
    return;
}

// 新方法
private bool ReadBombPressed()
{
    Keyboard keyboard = Keyboard.current;

    if (keyboard == null)
    {
        return false;
    }

    return keyboard.eKey.wasPressedThisFrame ||
           keyboard.spaceKey.wasPressedThisFrame;
}

private void TryUseBomb()
{
    Vector2Int targetCell = currentCell + facing;

    if (maze.GetTileType(targetCell) != TileType.Stone)
    {
        Debug.Log("这里没有灰色石头。");
        return;
    }

    if (!stats.TryConsumeBomb())
    {
        Debug.Log("没有炸弹了。");
        return;
    }

    if (maze.TryBreakStone(targetCell))
    {
        Debug.Log("灰色石头被炸开了。");
    }
}

// TryMove 最前面记录朝向
facing = direction;

顺序是“先确认前方是石头 → 再确认有炸弹 → 扣炸弹 → 改地图”。如果前方不是石头，炸弹不应该被消耗；这是资源系统最基本的一致性。

05

测试炸开一条路

  1. Play，确认 HUD 显示 炸弹: 1，石头在起点右侧。
  2. 按 D：玩家撞上石头，不会移动，但朝向变成右。
  3. 按 E：石头变成浅色地板，炸弹从 1 变成 0。
  4. 再按 D：玩家走进原来的石头格。
  5. 再按 E：前方没有石头，Console 提示“这里没有灰色石头”，炸弹仍为 0。
  6. 停止 Play，确认 Level_01 里的 S 还在；再 Play，石头重新出现。
这条验证很重要

如果停止 Play 后资产里的 S 消失了，说明你改到了 LevelDefinition 资产，而不是运行时副本。运行时破坏不应该污染内容模板。

检索练习：合上资料再答

先不要往上翻。答错没关系，努力回忆本身就在加固记忆。

1. 为什么炸石头不直接修改 LevelDefinition？

ScriptableObject 是磁盘资产；运行时破坏应写进内存副本，否则会污染关卡模板。

2. 石头被炸掉后，应该同时更新什么？

逻辑格子和 SpriteRenderer 必须同步，否则会出现“能走但还显示石头”或相反的问题。

3. 什么时候应该扣炸弹？

先验证目标和资源，再提交消耗；失败操作不应该扣资源。

4. facing 的作用是什么？

facing 记录最后一次移动方向，炸弹就作用于前方那一格。

报错急救

现象最可能原因处理
石头是洋红色ColorFor 没有 Stone 分支加入灰色分支，并确认 LevelDefinition 的 S 映射。
按 E 没反应朝向不对，或前方不是石头先朝石头方向按一次移动键，再按 E。
炸弹扣了，石头还在TryBreakStone 没有更新副本或渲染器检查 _tiles[x,y] 与 _renderers[x,y]。
没石头也扣炸弹先扣资源后验证先检查 TileType.Stone，通过后再消耗。
石头永远消失改了 LevelDefinition 资产只改 _tiles 副本，不要写回资产。
炸开后仍走不进去IsWalkable 还在查资产或仍排除 Stone确认 IsWalkable 读取 _tiles，且 Stone 只在破坏前阻挡。
HUD 没有炸弹HUD 没加行或 PlayerStats 没更新盒子高度改 132，加入 Bombs 标签。
