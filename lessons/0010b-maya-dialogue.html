MAYA 开口以后

上一课只显示了一句通关提示。今天把一句静态文字变成一段由玩家控制的对话：逐字出现、可以立即显示全句、最后再开放重开或下一关。

50–70 分钟 string[] · IEnumerator · Input System 产出：可推进的 MAYA 对话

本课胜利条件

为什么不能只把一句话变长

把整段话一次性塞进 TMP 文本，会有三个问题：玩家控制不了节奏、无法知道当前读到第几句、按钮出现时机也没有单独状态。对话需要一个小型队列。

DATA

对白属于关卡

台词放在 LevelDefinition 资产里，不写在 GameHud 的 if 中。

VIEW

视图只管显示

MayaDialogueView 维护第几句、是否正在打字，以及文字是否显示完整。

FLOW

流程决定时机

GameHud 只在 Completed 时开对话；Failed 直接进入失败结算。

MAYA · 通讯接入

对话 1 / 3

先玩一下上面的反馈环：第一次点击要能跳过逐字动画，第二次才切换句子。

01

把对白放进关卡资产

在 LevelDefinition.cs 加入对白数组和只读属性：

LevelDefinition.cs
[SerializeField] private string[] completionDialogue;

public string[] CompletionDialogue =>
    completionDialogue;

再让流程控制器公开当前关卡，供 UI 读取台词：

LevelFlowController.cs
public LevelDefinition CurrentLevel =>
    maze != null ? maze.CurrentLevel : null;

这样做以后，新增关卡只需要填台词，不需要再改 GameHud。

02

先把对话状态说清楚

在 Assets/Scripts 新建 MayaDialogueView.cs。它只保存四项关键状态：

状态回答的问题
_lines这次要依次显示哪些句子？
_lineIndex现在正在读第几句？
_lineIsComplete当前这句已经完整显示了吗？
IsShowing整个对话是否仍在进行？
输入规则

正在打字时，第一次推进输入只补全当前句；已经补全后，下一次推进输入才换到下一句。这样快速连点不会意外跳过整段剧情。

03

用协程制造逐字效果

协程会跨帧暂停和继续，适合“每隔一点时间多显示几个字”。它不是后台线程，TMP 文本仍然只在主线程更新。官方说明见 Unity Manual: Coroutines。

MayaDialogueView.cs · TypeLine
private IEnumerator TypeLine(string line)
{
    float visibleCharacters = 0f;
    bodyText.text = string.Empty;

    while (visibleCharacters < line.Length)
    {
        visibleCharacters +=
            charactersPerSecond *
            Time.unscaledDeltaTime;

        int count = Mathf.Min(
            line.Length,
            Mathf.FloorToInt(visibleCharacters));

        bodyText.text = line.Substring(0, count);
        yield return null;
    }

    bodyText.text = WithContinueCue(line);
    _lineIsComplete = true;
}

使用 Time.unscaledDeltaTime，界面动画不会因为 Time.timeScale 的变化而冻结。完整实现：MayaDialogueView.cs。

在 Awake 中把 bodyText.verticalAlignment 设为 Top。动态文本会从顶部向下生长，而不是随着行数变化重新居中或向上顶。

04

让 GameHud 接上对话

给 GameHud 增加一个对话引用，并在 Start 中订阅结束事件：

GameHud.cs · 引用
[SerializeField] private MayaDialogueView dialogue;

dialogue.Finished += HandleDialogueFinished;

GameHud 的 Update 只在对话打开时读取推进输入：

GameHud.cs · 推进输入
if (!dialogue.IsShowing)
{
    return;
}

bool advance =
    keyboard.spaceKey.wasPressedThisFrame ||
    keyboard.enterKey.wasPressedThisFrame ||
    mouse.leftButton.wasPressedThisFrame;

if (advance)
{
    dialogue.Advance();
}

完成状态先隐藏两个按钮并开始对话；失败状态直接显示重开：

GameHud.cs · 状态分支
if (flow.State == LevelState.Failed)
{
    dialogue.HideImmediate();
    restartButton.gameObject.SetActive(true);
    nextLevelButton.gameObject.SetActive(false);
    return;
}

restartButton.gameObject.SetActive(false);
nextLevelButton.gameObject.SetActive(false);
dialogue.Show(flow.CurrentLevel.CompletionDialogue);

对话结束时要把面板从“通讯态”切回“结算态”，否则标题会一直停留在通讯接入：

GameHud.cs · Finished
private void HandleDialogueFinished()
{
    endTitleText.text = "关卡完成";
    restartButton.gameObject.SetActive(true);
    nextLevelButton.gameObject.SetActive(
        flow.CanAdvance);
}

完整接线见 GameHud.cs、LevelFlowController.cs 和 LevelDefinition.cs。

05

配置面板、文字与两关对白

在 GameUI 上添加 MayaDialogueView：

字段绑定或数值
Body Text现有的 EndHintText
Characters Per Second28–36，先用 32

把 EndHintText 的 RectTransform 调整到约 540 × 120，Y 约为 10；Vertical Alignment 必须选 Top。EndTitleText 上移，运行时显示“通讯接入”。

不要用 Bottom 对齐

“继续”提示会追加两行文字。底部对齐时，新增行会从底边向上生长，导致已经读到的正文突然上移并撞到标题。顶部对齐能固定第一行位置。

在两个关卡资产中填写 Completion Dialogue，例如：

关卡建议对白
Level_FlowTest“材料拿到了。” / “前面是熔岩区。石头会挡住你，但不会主动追来。” / “我找到下一条线索了。准备好就出发。”
Level_05“我们穿过了熔岩区。” / “这次没有新的地点可去，但这只是旅程的停顿。”
先检查空数组

最后一关也必须配置对白。若数组为空，代码仍应显示一句保底文本，而不是留下空白面板。

06

测试节奏与状态边界

  1. 完成 Level_FlowTest：标题变为 MAYA，第一句逐字出现，操作按钮不可见。
  2. 打字过程中点击一次：当前句立即完整显示，但不会跳到下一句。
  3. 再次点击或按空格：进入第二句。最后一句后再推进，才出现“重开”和“下一关”。
  4. 进入 Level_05：看到不同对白；读完最后一句后只出现“重开”，没有“下一关”。
  5. 让生命耗尽：不播放 MAYA 通关对话，直接显示失败结算。
  6. 对话中按 R：重开后的关卡与 HUD 不残留旧台词。

检索练习

先不要往上翻。

1. 为什么把通关台词放进关卡资产？

内容属于关卡数据，显示逻辑与推进逻辑不需要为每一关复制。

2. 正在逐字显示时第一次推进输入做什么？

这是“跳过动画但不跳剧情”的两层输入规则。

3. 对话文字为何使用 unscaledDeltaTime？

UI 的显示节奏不应依赖游戏世界的 timeScale。

4. 什么时候显示重开和下一关按钮？

玩家先读完剧情，再得到下一步操作；失败则走独立分支。

报错急救

现象处理
完成后没有文字MayaDialogueView 是否绑定 EndHintText，关卡数组是否有内容。
一次输入跳过两句同一帧是否被 Update 和按钮各推进了一次；只保留一条输入路径。
文字停在一半协程是否被 StopCoroutine 后没有补全；检查 Advance 分支。
继续提示出现后文本上移EndHintText 是否仍是 Bottom 对齐；改为 Top，并扩大文本框。
按钮提前出现Completed 分支是否在 Show 前把按钮设为 false。
失败也出现 MAYAFailed 分支是否先 HideImmediate，并提前 return。
重新进关残留文字HideImmediate 是否清理数组、索引、协程和 TMP 文本。
