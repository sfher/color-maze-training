色彩迷宫 · 开发实训 / 课程 03

把关卡从代码里
搬出来

现在每加一个关卡都要改 C#，这不是做内容的方式。今天把地图搬进一个可编辑的 LevelDefinition 资产，让关卡变成数据，而不是代码。

50–75 分钟 ScriptableObject · 数据 · 重构 产出：可编辑的关卡资产

本课胜利条件

为什么现在重构

你现在的 MazeBootstrapper 里同时有：地图字符串、尺寸常量、渲染逻辑、可通行判断。只有一关时它很好用；但《色彩迷宫》要做的是多个关卡，继续这样写会出现三个问题：

  • 每加一关都要复制或修改脚本，代码和内容纠缠在一起。
  • 地图数据藏在字符串拼接里，改错一个字符很难定位。
  • 以后想让“关卡设计”和“程序实现”分开，没有清晰的边界。

今天引入 ScriptableObject：一种存放在 Assets 里、可以被 Inspector 编辑、但不挂在场景对象上的数据资产。它很适合关卡、道具表、数值配置。

Data

LevelDefinition

保存地图行、尺寸与格子查询。它只回答“这一格是什么”，不负责生成方块。

View / Query

MazeBootstrapper

读取关卡数据，生成方块，回答“这一格能不能走”。它不再拥有地图内容。

Input

PlayerGridMover

只负责读取按键、询问目标格是否可走、更新玩家位置。

00

先清理两个技术债

打开 Hierarchy，展开 Player。你会看到一个名为 PlayerGridMover 的子对象，它的组件引用是空的。它是重复对象，会让 Console 报错；选中这个子对象并删除，保留 Player 本身和它身上的 Player Grid Mover 组件。

然后打开 Assets/Scripts/MazeBootstrapper.cs，确认文件顶部没有这两行：

using JetBrains.Annotations;
using UnityEditor.Tilemaps;

它们没有被用到；其中 UnityEditor.Tilemaps 属于编辑器程序集，运行时代码引用它，在编辑器里可能正常，但打包 Windows 版本时会失败。运行时代码只应该依赖 UnityEngine；编辑器工具代码要放在单独的 Editor/ 目录或用条件编译隔离。

这是行业里很常见的坑

“编辑器里能跑”不等于“能打包”。每次引入一个命名空间，都要问：它属于运行时还是编辑器？UnityEditor 开头的类型，默认不能出现在玩家的构建里。

01

创建 LevelDefinition.cs

在 Assets/Scripts 右键，选择 Create → C# Script，命名为 LevelDefinition。替换为：

LevelDefinition.cs
using UnityEngine;

[CreateAssetMenu(
    menuName = "Color Maze/Level Definition",
    fileName = "Level_01")]
public class LevelDefinition : ScriptableObject
{
    [SerializeField] private string[] rows =
    {
        "#######",
        "#.....#",
        "#.RR..#",
        "#.....#",
        "#..BB.#",
        "#.....#",
        "#######"
    };

    public int Width => rows != null && rows.Length > 0
        ? rows[0].Length
        : 0;

    public int Height => rows != null ? rows.Length : 0;

    public bool Contains(Vector2Int cell)
    {
        return cell.x >= 0 && cell.x < Width &&
               cell.y >= 0 && cell.y < Height;
    }

    public char GetTile(Vector2Int cell)
    {
        int row = Height - 1 - cell.y;
        return rows[row][cell.x];
    }

    private void OnValidate()
    {
        if (rows == null || rows.Length == 0)
        {
            Debug.LogWarning("LevelDefinition: 地图至少需要一行。", this);
            return;
        }

        int width = rows[0].Length;

        for (int i = 0; i < rows.Length; i++)
        {
            if (string.IsNullOrEmpty(rows[i]) ||
                rows[i].Length != width)
            {
                Debug.LogWarning(
                    $"LevelDefinition: 第 {i + 1} 行长度不一致，应为 {width}。",
                    this);
            }
        }
    }
}

这里有几个新概念：

  • ScriptableObject 是一个可序列化的数据对象，不会像 MonoBehaviour 那样挂在场景对象上。
  • [CreateAssetMenu] 会在 Project 窗口的 Create 菜单里增加一个入口，方便创建资产。
  • rows 是逐行地图，数组第一项是顶部行；GetTile 把 y 轴翻回 Unity 的方向。
  • OnValidate 只用于编辑器里的数据检查：行长不一致时在 Console 给出警告，而不是等到运行时才崩。
02

让 MazeBootstrapper 读取关卡资产

用下面的版本替换 MazeBootstrapper.cs。渲染逻辑和颜色逻辑保持原样，变化在于地图不再写死在脚本里。

MazeBootstrapper.cs · 重构后
using UnityEngine;

public class MazeBootstrapper : MonoBehaviour
{
    [SerializeField] private LevelDefinition level;

    private int Width => level != null ? level.Width : 0;
    private int Height => level != null ? level.Height : 0;

    private void Start()
    {
        if (level == null)
        {
            Debug.LogError(
                "MazeBootstrapper: 请在 Inspector 里指定 Level Definition。",
                this);
            enabled = false;
            return;
        }

        Sprite square = CreateSquareSprite();

        for (int y = 0; y < Height; y++)
        {
            for (int x = 0; x < Width; x++)
            {
                char tile = level.GetTile(new Vector2Int(x, y));
                CreateCell(square, x, y, tile);
            }
        }
    }

    public bool IsWalkable(Vector2Int cell)
    {
        if (level == null || !level.Contains(cell))
        {
            return false;
        }

        return level.GetTile(cell) != '#';
    }

    public Vector3 CellToWorld(Vector2Int cell)
    {
        return transform.TransformPoint(CellToLocal(cell));
    }

    private Vector3 CellToLocal(Vector2Int cell)
    {
        return new Vector3(
            cell.x - (Width - 1) * 0.5f,
            cell.y - (Height - 1) * 0.5f,
            0f);
    }

    private void CreateCell(Sprite square, int x, int y, char tile)
    {
        GameObject cell = new GameObject($"Cell_{x}_{y}");
        cell.transform.SetParent(transform);
        cell.transform.localPosition = CellToLocal(new Vector2Int(x, y));

        SpriteRenderer spriteRenderer = cell.AddComponent<SpriteRenderer>();
        spriteRenderer.sprite = square;
        spriteRenderer.color = ColorFor(tile);
    }

    private Color ColorFor(char tile)
    {
        switch (tile)
        {
            case '#': return new Color(0.10f, 0.10f, 0.12f);
            case '.': return new Color(0.93f, 0.92f, 0.88f);
            case 'R': return new Color(0.82f, 0.22f, 0.20f);
            case 'B': return new Color(0.16f, 0.45f, 0.86f);
            default: return Color.magenta;
        }
    }

    private Sprite CreateSquareSprite()
    {
        Texture2D texture = new Texture2D(1, 1);
        texture.SetPixel(0, 0, Color.white);
        texture.Apply();

        return Sprite.Create(
            texture,
            new Rect(0f, 0f, 1f, 1f),
            new Vector2(0.5f, 0.5f),
            1f);
    }
}

注意：脚本文件名必须仍然是 MazeBootstrapper.cs，这样场景里已经挂好的组件引用不会断。等 Unity 编译完成后，Inspector 里会多出一个 Level 字段，现在是 None。

03

创建 Level_01 资产并绑定

  1. 在 Project 窗口右键 Assets，选择 Create → Folder，命名 Data。
  2. 右键 Data，选择 Create → Color Maze → Level Definition，命名为 Level_01。
  3. 选中 Level_01，在 Inspector 里确认 Rows 有 7 个元素，内容与原来的地图一致。
  4. 选中挂了 MazeBootstrapper 的对象，把 Level_01 从 Project 窗口拖到它的 Level 字段。
  5. 按 Play。画面应该与第一课完全一致，玩家仍然可以移动。
本课真正的胜利

停止 Play，在 Level_01 里把某一行改一个字符，例如把 #.RR..# 改成 #.R...#，再 Play。画面立刻变化，而你一行 C# 都没改。这就是“数据驱动内容”。

如果 Rows 显示为空，检查脚本是否编译成功、类名和文件名是否一致；创建资产时字段初始化器应该自动填入默认地图。

04

可选挑战：做第二关

选中 Level_01，按 Ctrl + D 复制，命名为 Level_02，改几行地图，再把 Maze 的 Level 字段换成它。确认：

  • 两个关卡使用同一套脚本；
  • 切换资产就能切换内容；
  • 所有行长度一致，否则 OnValidate 会在 Console 提醒。

如果第二关的起点 (1,1) 是墙，玩家会出生在墙里但无法移动；先把起点改成可走格，或者暂时把 Start Cell 调整到合适位置。

检索练习：合上资料再答

先不要往上翻。答错没关系，努力回忆本身就在加固记忆。

1. ScriptableObject 最适合承担下面哪件事？

ScriptableObject 是数据资产，适合关卡、道具表和数值配置；输入和渲染仍由运行时组件负责。

2. [CreateAssetMenu] 的作用是什么？

它把“创建这种数据资产”的入口加到 Project 窗口的 Create 菜单里，方便策划或开发者新建关卡。

3. 为什么运行时代码不能引用 UnityEditor？

UnityEditor 只存在于编辑器环境；玩家构建里没有这组程序集，所以运行时代码不能依赖它。

4. 把地图放进 LevelDefinition 的最大收益是什么？

关卡内容变成可编辑资产，新增或调整关卡不需要改动 C#，也让内容与程序职责分开。
