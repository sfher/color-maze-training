本课胜利条件

三层结构与数据流

架构
ContentEntry（资产）    一条商品：id / 名称 / 类型 / 价格 / 载体引用
ContentCatalog（资产）  货架：全部条目 + 查询 + 换装/换皮解析
ProgressService（场景） 唯一的存档持有者：
                          TryPurchase → 扣金币 + 解锁
                          Equip       → 写装备位
                          SettleLevelComplete → 金币结算 + 首通
                          IsLevelPlayable     → 顺序解锁 / 购买解锁

为什么存档只能有一个持有者：设置面板、商店、结算都会改存档，如果各自加载/保存，后写的会把先写的覆盖掉。所以本课把 13 课的 SaveCoordinator 升级成 ProgressService——设置读写逻辑原样保留，新职责全部加在这里。

03

ProgressService：唯一的存档持有者（完整代码）

这是本课的主体，完整文件在 solutions/0020/ProgressService.cs。要点逐个讲：

  • 接管 SaveCoordinator：场景里把 SaveCoordinator 组件换成 ProgressService，settings 引用重绑。Save() 仍然是"先 CaptureTo 再写盘"，设置面板零改动。
  • TryPurchase：判定顺序 Invalid → AlreadyOwned → NotEnoughCoins → 扣币 + 解锁 + 立即写盘 + 发 Changed 事件（16c 的商店 UI 靠它刷新）。
  • Equip：只允许装备已解锁条目；写存档的同时同步 GameSession，这样下一局开场就能应用。
  • SettleLevelComplete：本局 PlayerStats.Coins 入档 + 首通 +10（用 completedLevelIds 判重）+ lastLevelId 推进到下一关（尽头保持当前关）。
  • IsLevelPlayable：目录里有条目的关卡按购买判定；主线按"通关 N 解锁 N+1"沿 NextLevel 链走。
  • DeleteSave：删磁盘档（含 backup）+ 内存重置，16b 主菜单的"清空存档"直接调它。
防刷的关键是位置

结算只挂在"进入 Completed 状态"这一条路径上（下一步的 ReachExit）——失败、重开、步数耗尽都不会经过它，所以不需要任何额外的防重复计数。别把结算挪到 Update 或 UI 事件里。

装备的应用链（完整代码）

新组件 PlayerSkinApplier.cs（挂在 Player 上）：

PlayerSkinApplier.cs · 完整
using UnityEngine;

public class PlayerSkinApplier : MonoBehaviour
{
    [SerializeField] private ContentCatalog catalog;
    [SerializeField] private SpriteRenderer spriteRenderer;

    private void Start()
    {
        if (catalog == null || spriteRenderer == null)
        {
            return;
        }

        Sprite skin =
            catalog.ResolveSkin(GameSession.EquippedSkinId);

        if (skin != null)
        {
            spriteRenderer.sprite = skin;
        }
    }
}

MazeBootstrapper.cs 两处改动（完整版在 solutions/0020）：字段 visuals 改名 defaultVisuals、新增 [SerializeField] ContentCatalog cosmeticsCatalog 与私有 _activeVisuals；Start 判空之后加主题解析：

_activeVisuals = defaultVisuals;

if (cosmeticsCatalog != null)
{
    TileVisuals themed = cosmeticsCatalog.ResolveVisuals(
        GameSession.EquippedThemeId);

    if (themed != null)
    {
        _activeVisuals = themed;
    }
}

之后 CreateCell / TryReplace 全部读 _activeVisuals。主题下一局生效就是这句的语义：进关时解析一次。

if (hasMaterial)
