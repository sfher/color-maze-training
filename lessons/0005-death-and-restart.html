色彩迷宫 · 开发实训 / 课程 05

死亡不是卡住
是一个状态

生命归零后，玩家现在只是“不能动了”，但游戏没有告诉他发生了什么，也没有回来的路。今天补上失败状态、提示和按 R 重开。

45–60 分钟 事件 · 场景 · 失败流程 产出：可重开的失败循环

本课胜利条件

为什么用事件，而不是每帧检查

失败提示需要知道“生命刚刚变成 0”。最直接的做法是让 GameOverController 每帧读 playerStats.Health，但这样会让 UI 和数值系统一直互相盯着。更清晰的方式是让 PlayerStats 在死亡时发一个通知：

发布 / 订阅

PlayerStats 负责宣布“我死了”；GameOverController 负责决定“死了以后显示什么”。双方不需要知道对方的内部细节。

这就是 C# 的 event：发布者只在状态变化时触发，订阅者决定要做什么。注意，事件适合“一次性状态变化”，不适合代替所有方法调用。

01

让 PlayerStats 宣布死亡

打开 PlayerStats.cs，加入事件字段和一次性保护：

PlayerStats.cs · 新增字段
public event System.Action Died;

private bool _deathAnnounced;

然后修改 LoseHealth，在生命归零时通知订阅者：

PlayerStats.cs · LoseHealth
private void LoseHealth(int amount)
{
    Health = Mathf.Max(0, Health - amount);
    Debug.Log($"生命 -{amount}，剩余 {Health}");

    if (Health == 0 && !_deathAnnounced)
    {
        _deathAnnounced = true;
        Died?.Invoke();
    }
}

Died?.Invoke() 的意思是：如果现在有订阅者，就通知它们；没有订阅者也不会报错。_deathAnnounced 保证死亡事件只发一次，避免后续重复调用 LoseHealth 时反复弹提示。

02

创建 GameOverController.cs

在 Assets/Scripts 新建 C# 脚本 GameOverController，替换为：

GameOverController.cs
using UnityEngine;
using UnityEngine.InputSystem;
using UnityEngine.SceneManagement;

public class GameOverController : MonoBehaviour
{
    [SerializeField] private PlayerStats playerStats;

    private bool _isGameOver;
    private GUIStyle _titleStyle;
    private GUIStyle _hintStyle;

    private void Start()
    {
        if (playerStats == null)
        {
            Debug.LogError(
                "GameOverController: 请指定 PlayerStats。",
                this);
            enabled = false;
            return;
        }

        playerStats.Died += HandlePlayerDied;
    }

    private void OnDestroy()
    {
        if (playerStats != null)
        {
            playerStats.Died -= HandlePlayerDied;
        }
    }

    private void Update()
    {
        if (!_isGameOver)
        {
            return;
        }

        Keyboard keyboard = Keyboard.current;

        if (keyboard != null && keyboard.rKey.wasPressedThisFrame)
        {
            SceneManager.LoadScene(
                SceneManager.GetActiveScene().buildIndex);
        }
    }

    private void HandlePlayerDied()
    {
        _isGameOver = true;
    }

    private void OnGUI()
    {
        if (!_isGameOver)
        {
            return;
        }

        GUI.depth = -10;
        GUI.color = new Color(0f, 0f, 0f, 0.68f);
        GUI.DrawTexture(
            new Rect(0f, 0f, Screen.width, Screen.height),
            Texture2D.whiteTexture);
        GUI.color = Color.white;

        if (_titleStyle == null)
        {
            _titleStyle = new GUIStyle(GUI.skin.label)
            {
                fontSize = 42,
                alignment = TextAnchor.MiddleCenter,
                fontStyle = FontStyle.Bold
            };
            _titleStyle.normal.textColor = Color.white;

            _hintStyle = new GUIStyle(GUI.skin.label)
            {
                fontSize = 24,
                alignment = TextAnchor.MiddleCenter
            };
            _hintStyle.normal.textColor = new Color(1f, 0.85f, 0.45f);
        }

        GUI.Label(
            new Rect(0f, Screen.height * 0.5f - 70f, Screen.width, 60f),
            "生命耗尽",
            _titleStyle);
        GUI.Label(
            new Rect(0f, Screen.height * 0.5f + 10f, Screen.width, 40f),
            "按 R 重开",
            _hintStyle);
    }
}

三个关键点：

  • Start 里订阅，OnDestroy 里取消订阅。订阅和取消成对出现，避免对象销毁后事件还指向一个空对象。
  • Update 只在 _isGameOver 为真时处理 R；平时不响应重开键。
  • SceneManager.LoadScene 重载当前场景，场景里的对象、生命、氧气、玩家位置都会回到初始状态。
03

搭一个 GameManager 对象

  1. 菜单 GameObject → Create Empty，命名为 GameManager。
  2. 给 GameManager 添加 GameOverController 组件。
  3. 把 Player 拖到 GameOverController 的 Player Stats 字段；Unity 会从 Player 上找到 PlayerStats 组件。
  4. 确认 Player 上仍然有 PlayerStats 和 PlayerGridMover，并且 Maze 引用没有丢。
  5. 打开 File → Build Profiles（旧版叫 Build Settings），在 Scene List 里确认 Assets/Scenes/Main.unity 已启用。你的工程目前已经包含它，检查一下即可。
为什么需要 Build Settings

SceneManager.LoadScene 只能加载已经加入构建场景列表的场景。编辑器里能打开 Main，不代表运行时能按名字/索引加载它。

04

测试一次完整的失败与重开

用 Level_01 测试。从起点 (1,1) 走到岩浆格 (2,4)，反复进出三次：

  1. W, W, W, D：进入 (2,4)，生命 3 → 2。
  2. A：回到 (1,4) 地板，生命仍是 2。
  3. D：再次进入 (2,4)，生命 2 → 1。
  4. A, D：再次进入，生命 1 → 0。

预期：玩家停止移动，屏幕变暗并显示“生命耗尽 / 按 R 重开”。按 R 后场景重载，HUD 回到 生命 3 / 3、氧气 3 / 3，玩家回到起点。

两套 OnGUI 的层级

PlayerStats 和 GameOverController 都用 OnGUI 画字。GameOverController 设置了 GUI.depth = -10，数值更小会画在更上层，所以失败提示应该盖住生命/氧气框。

检索练习：合上资料再答

先不要往上翻。答错没关系，努力回忆本身就在加固记忆。

1. Died 事件的主要作用是什么？

事件把“状态发生了变化”通知给订阅者，让 UI 或音效自行决定怎么响应。

2. 为什么要在 OnDestroy 里取消订阅？

对象销毁后，事件仍持有它的引用会造成悬空引用和潜在重复回调；成对订阅/取消订阅是基本纪律。

3. 重载场景前，Main 必须在哪里？

SceneManager.LoadScene 只能加载已加入构建场景列表的场景；编辑器打开过不算。

4. 为什么按 R 直接重载场景，而不是手动改数值？

场景重载会重建所有对象与状态，比逐个手动复位更不容易漏字段。
