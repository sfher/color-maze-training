把策划案变成
第一屏彩色迷宫

这一课不先学完 C#。我们先把《色彩迷宫》最重要的视觉承诺——“颜色即规则”——变成一个真的能按 Play 看见的 7×7 网格。

45–60 分钟 C# · Unity · Git 产出：可运行的颜色网格

本课胜利条件

为什么先做“这一屏”

策划案里已经有生命、氧气、传送门、商店和叙事。如果一次全做，你很快会同时面对十几个互相纠缠的问题：画面不对、输入没反应、数值扣错、关卡读不出来。到那时，你很难判断到底是哪一层坏了。

行业里常用的做法是先做一个 vertical slice（垂直切片）：只取一条最窄的完整路径，从数据到画面全部打通，证明“这个方向能跑”。本课的切片只有一件事：

本课的最小闭环

一张用字符写成的关卡地图 → C# 读取每个格子 → 在场景里生成对应颜色的方块。

这条路径打通后，后面所有规则——岩浆扣血、水耗氧、炸弹破石——都只是往这个循环里加判断，而不是重新搭一遍地基。

三个概念，够用了

GameObject

游戏对象

场景里的“东西”。它本身几乎是个空壳，靠组件获得能力。我们的每个格子、玩家、相机都是 GameObject。

Component

组件

挂在对象上的能力模块：Transform 给位置，SpriteRenderer 给图像，脚本给行为。一个对象可以挂很多组件。

Script

脚本

一段继承 MonoBehaviour 的 C# 类。挂到对象上后，Unity 会在特定时机调用它的 Start、Update 等方法。

记住一句话就够了：GameObject 是“谁”，Component 是“会什么”，Script 是“怎么动”。

行业习惯

模板只是起点。真正属于你的资产会放进一个独立目录，第三方插件和模板示例留在外面。这样项目变大后，你仍然知道哪些文件可以改、哪些最好不要碰。

02

建立目录与主场景

在 Unity 的 Project 窗口里，确认模板已经带了 Assets/Scenes 和 Assets/Settings。现在只额外建一个 Scripts 文件夹：右键 Assets，选择 Create → Folder，命名为 Scripts。

Assets/
├── Scenes/       # Main.unity
├── Scripts/      # 我们的 C# 脚本
├── Settings/     # URP 2D 与 Input Actions（模板自带，保留）
└── ...           # Art / Audio / Data / Prefabs 等到需要时再建

小项目用顶层文件夹完全够用。等以后导入第三方素材，再把“自己的内容”集中到 Assets/_Project 也不迟；不要为了目录好看提前建一堆空文件夹。关键是整个项目只用一种结构。

然后按 Ctrl + Shift + S，确认场景保存为 Assets/Scenes/Main.unity。模板自带的 SampleScene 可以保留；我们只使用 Main。

不要忽略 .meta

Unity 会为每个资产生成同名的 .meta 文件，里面记录 GUID 与导入设置。它们必须和资产一起提交到 Git，否则换一台电脑后，场景里的引用会全部丢失。

04

写第一个脚本：从字符到方块

在 Assets/Scripts 上右键，选择 Create → C# Script，命名为 MazeBootstrapper。文件名必须和类名一致，否则 Unity 不会把它挂到对象上。双击打开，替换为：

MazeBootstrapper.cs
using UnityEngine;

public class MazeBootstrapper : MonoBehaviour
{
    private const int Width = 7;
    private const int Height = 7;

    private const string MazeMap =
        "#######" +
        "#.....#" +
        "#.RR..#" +
        "#.....#" +
        "#..BB.#" +
        "#.....#" +
        "#######";

    private void Start()
    {
        Sprite square = CreateSquareSprite();

        for (int index = 0; index < MazeMap.Length; index++)
        {
            int x = index % Width;
            int y = Height - 1 - (index / Width);

            CreateCell(square, x, y, MazeMap[index]);
        }
    }

    private void CreateCell(Sprite square, int x, int y, char tile)
    {
        GameObject cell = new GameObject($"Cell_{x}_{y}");
        cell.transform.SetParent(transform);
        cell.transform.position = new Vector3(
            x - (Width - 1) * 0.5f,
            y - (Height - 1) * 0.5f,
            0f);

        SpriteRenderer spriteRenderer = cell.AddComponent<SpriteRenderer>();
        spriteRenderer.sprite = square;
        spriteRenderer.color = ColorFor(tile);
    }

    private Color ColorFor(char tile)
    {
        switch (tile)
        {
            case '#': return new Color(0.10f, 0.10f, 0.12f);
            case '.': return new Color(0.93f, 0.92f, 0.88f);
            case 'R': return new Color(0.82f, 0.22f, 0.20f);
            case 'B': return new Color(0.16f, 0.45f, 0.86f);
            default:  return Color.magenta;
        }
    }

    private Sprite CreateSquareSprite()
    {
        Texture2D texture = new Texture2D(1, 1);
        texture.SetPixel(0, 0, Color.white);
        texture.Apply();

        return Sprite.Create(
            texture,
            new Rect(0f, 0f, 1f, 1f),
            new Vector2(0.5f, 0.5f),
            1f);
    }
}

保存文件，回到 Unity，等右下角的编译转圈结束。如果 Console 出现红字，先不要继续，按本课最后的“报错急救”处理。

05

把它挂进场景，按下 Play

  1. 菜单 GameObject → Create Empty，把新对象命名为 Maze。
  2. 在 Inspector 里确认它的 Transform 是 Position (0,0,0)、Rotation (0,0,0)、Scale (1,1,1)。
  3. 把 MazeBootstrapper.cs 从 Project 窗口拖到 Maze 的 Inspector 上，或点 Add Component 搜索脚本名。
  4. 按 Play（Ctrl + P）。

你应该看到一块居中的 7×7 迷宫：黑色边框、浅色地板、两块红色岩浆、两块蓝色水。

预期画面（颜色为近似值）。方块之间出现的细线是 Sprite 边缘，不是逻辑错误。

Play 模式里的修改会消失

在 Play 模式中拖动对象、改数值，停止后会恢复。把 Play 模式当成“试运行”，不要在里面积累正式修改；要改就停下来改。

06

读懂这 50 行

现在不需要背语法，但要知道每一层在做什么：

  • Start() 在对象启用后的第一帧前执行一次。我们在这里生成整张地图。
  • MazeMap 是一个 49 个字符的字符串，每 7 个字符代表一行。字符就是数据：# 墙、. 地板、R 岩浆、B 水。
  • index % Width 取余数，得到列号；index / Width 取整数商，得到行号。这是网格编程里最常用的两个运算。
  • Height - 1 - (index / Width) 把“字符串从上往下读”翻成“世界坐标从下往上长”，所以第一行会出现在顶部。
  • new GameObject(...) 创建对象，AddComponent<SpriteRenderer>() 给它加渲染能力，SetParent(transform) 让 49 个格子都归 Maze 管理。
  • CreateSquareSprite() 在运行时生成一张 1×1 的白色贴图，这样第一课不需要任何美术资源。颜色由 SpriteRenderer.color 染上去。
  • ColorFor 用 switch 把字符翻译成颜色。出现洋红色，说明地图里有一个没被识别的字符——这是故意的调试信号。
诚实的技术债

这段代码把尺寸写了两遍，把地图和颜色写死在脚本里。它适合验证第一屏，不适合做十个关卡。第 03 课会把关卡搬到 ScriptableObject 数据资产里。先承认技术债，再计划偿还，是工程判断的一部分。

检索练习：合上资料再答

先不要往上翻。答错没关系，努力回忆本身就在加固记忆。

1. 在 Unity 里，挂载脚本、拥有位置和旋转的最小场景单位是什么？

GameObject 是容器；Transform 组件给它位置与旋转，脚本只是挂在它上面的组件之一。

2. Start() 在什么时候执行？

Start 只在对象启用后、第一帧更新前执行一次；每帧执行的是 Update。

3. index % 7 用来算方块在网格里的什么？

取余得到列号，整数除法得到行号。两者合起来，就把一维字符位置映射成了二维网格坐标。

4. 先用字符串写地图，最大的工程收益是什么？

地图数据独立于生成逻辑，易读、易改、易比较；以后换成 ScriptableObject 时，渲染循环可以保持不变。

报错急救

现象最可能原因处理
Console 红字，无法进入 Play脚本有编译错误双击第一条红字，看行号；先修第一条，后面的错误常常会一起消失。
Game 视图什么都没有脚本没挂上，或对象被禁用选中 Maze，确认 Inspector 里有 MazeBootstrapper 组件；检查对象名称是否变灰。
方块是洋红色MazeMap 里有未识别字符，或字符总数不是 49检查每个字符只能是 # . R B；每行必须正好 7 个。
只看到一部分，或完全偏出画面相机位置/正交尺寸不匹配选中 Main Camera，把 Position 设为 (0,0,-10)，Orthographic Size 设为 5。
改了代码没反应文件没保存，或还在 Play 模式保存脚本，等编译结束；停止 Play 后再改场景。
