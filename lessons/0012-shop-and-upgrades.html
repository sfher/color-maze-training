MAYA 补给站

宝箱里的金币终于有用途了。关卡完成后打开补给站，用本轮运行累计的金币购买强化；强化在下一关生效，并在场景重载后保留，但关闭游戏后仍会清零。

60–90 分钟 ScriptableObject · PurchaseResult · 字典 产出：可消费的 MAYA 补给站
暂时搁置

本课保留但不继续实现。金币暂不购买数值强化；先完成主题、图片、额外关卡等可购买内容，再回来重建商店。

本课胜利条件

购买是一次可能失败的交易

只返回 bool，调用方只知道“失败”，却不知道是余额不足、已经满级，还是强化资产忘了绑定。补给站需要能显示准确的反馈，所以购买结果应该是一个小枚举。

DATA

强化是资产

名称、类型、满级与价格阶梯放在 ScriptableObject 中。

MODEL

交易只改进度

PlayerProgress 验证余额和等级，并原子地扣费、升级。

VIEW

界面显示结果

PurchaseResult 决定成功、余额不足、满级或配置错误文案。

本次运行金币 6
氧气上限 3

购买一次，再让余额不足或升级满级。

01

定义强化类型与结果

先建立三个很小的领域类型，不依附于任何 UI：

UpgradeType.cs / PurchaseResult.cs
public enum UpgradeType
{
    MaxHealth,
    OxygenCapacity,
    StartingBombs
}

public enum PurchaseResult
{
    Purchased,
    NotEnoughCoins,
    MaxLevel,
    InvalidUpgrade
}

枚举让调用方使用有限、可读的状态，不再比较数字或猜测失败原因。

02

让强化内容成为资产

新增 UpgradeDefinition。每个资产配置一种强化，并提供按当前等级计算价格的方法：

UpgradeDefinition.cs
[CreateAssetMenu(
    menuName = "Color Maze/Upgrade Definition")]
public class UpgradeDefinition : ScriptableObject
{
    [SerializeField] private UpgradeType type;
    [SerializeField] private string displayName;
    [SerializeField, Min(0)] private int maxLevel = 2;
    [SerializeField, Min(0)] private int baseCost = 3;
    [SerializeField, Min(0)] private int costStep = 2;

    public int CostFor(int currentLevel)
    {
        return baseCost +
            Mathf.Max(0, currentLevel) * costStep;
    }
}

在 Project 中创建三份资产：生命上限、氧气上限、初始炸弹。价格可以先用生命 4/6、氧气 3/5、炸弹 2/4。

03

把金币和等级放进 PlayerProgress

PlayerProgress 不继承 MonoBehaviour，只保存本轮运行的数据：

PlayerProgress.cs · 状态
private readonly Dictionary<UpgradeType, int>
    _levels = new Dictionary<UpgradeType, int>();

public event Action Changed;
public int Coins { get; private set; }

public int GetLevel(UpgradeType type)
{
    return _levels.TryGetValue(type, out int level)
        ? level
        : 0;
}

每个强化只保存当前等级，不保存“最终生命值”。新关卡应该先重新生成完整基础属性，再应用等级加成。

04

写出不会半成功的 TryPurchase

购买顺序固定为：验证资产 → 验证满级 → 验证金币 → 扣费并升级 → 发布变化。

PlayerProgress.cs · TryPurchase
if (upgrade == null)
    return PurchaseResult.InvalidUpgrade;

int level = GetLevel(upgrade);
if (level >= upgrade.MaxLevel)
    return PurchaseResult.MaxLevel;

int cost = upgrade.CostFor(level);
if (Coins < cost)
    return PurchaseResult.NotEnoughCoins;

Coins -= cost;
_levels[upgrade.Type] = level + 1;
Changed?.Invoke();
return PurchaseResult.Purchased;
失败分支不扣钱

所有 return 都发生在 Coins -= cost 之前。新增失败原因时也必须保持这个顺序。

05

用运行会话保留跨关进度

GameSession 持有一个 PlayerProgress，停止 Play 时创建新实例：

GameSession.cs
public static PlayerProgress Progress { get; private set; }
    = new PlayerProgress();

private static void ResetOnPlay()
{
    CurrentLevel = null;
    Progress = new PlayerProgress();
}

PlayerStats 不再自己保存金币，而是从 GameSession.Progress 读取，并在下一关 Awake 时应用强化等级。

06

PlayerStats 只计算当前属性

把固定的上限改成计算属性：

PlayerStats.cs
public int MaxHealth =>
    StartingMaxHealth +
    GameSession.Progress.GetLevel(
        UpgradeType.MaxHealth);

public int MaxOxygen =>
    StartingMaxOxygen +
    GameSession.Progress.GetLevel(
        UpgradeType.OxygenCapacity);

Awake 时让生命与氧气以新上限填满，并让初始炸弹等于基础值加购买等级。GameHud 改成读取 playerStats.MaxHealth、playerStats.MaxOxygen 和 playerStats.Coins。

07

生成可重复的强化行

UpgradeShop 持有可由 Inspector 配置的 UpgradeRow[]。每一行绑定强化资产、按钮和 TMP 标签：

UpgradeShop.cs · 行数据
[Serializable]
private class UpgradeRow
{
    [SerializeField] private UpgradeDefinition definition;
    [SerializeField] private Button button;
    [SerializeField] private TMP_Text label;
}

Awake 中统一注册按钮，OnDestroy 中统一移除。不要在 Inspector 里为每个按钮手绑不同代码入口。

为什么用 Awake，不是 Start

GameHud 在 Start 中可能立刻隐藏 ShopPanel。若 UpgradeShop 也在 Start 才注册按钮，组件可能先被关闭，无法保证 Start 已经执行。Awake 在对象首次激活时必定先于所有 Start。

08

刷新等级、价格与结果

每行显示当前等级、当前价格和下一关效果。未满级时，按钮还要检查金币：

UpgradeShop.cs · Refresh
int level = progress.GetLevel(row.Definition);
int cost = row.Definition.CostFor(level);

row.Label.text =
    $"{row.Definition.DisplayName}\n" +
    $"Lv.{level}/{row.Definition.MaxLevel}" +
    $" · {cost} 金币";

row.Button.interactable =
    progress.Coins >= cost;

点击后把 PurchaseResult 映射为反馈文案；按钮禁用只是提示，TryPurchase 仍是最终防线。

09

接入结算面板并测试

创建全屏 UpgradeShopPanel，包含钱包、结果文本、三行强化和关闭按钮。场景初始保持面板激活，让 UpgradeShop 的 Awake 完成注册；GameHud 启动后和失败/重开时调用 Hide()，对话结束时调用 Show()。

  1. 金币不足：按钮不可点；直接调用模型仍返回 NotEnoughCoins，余额不变。
  2. 购买炸弹：金币减少、等级 +1、下一关炸弹增加。
  3. 连续购买直到满级：按钮禁用，余额不再减少。
  4. 关闭补给站：重开与下一关按钮可点击。
  5. 进入下一关：生命、氧气、炸弹按购买等级初始化。
  6. 停止 Play 再进入：金币、等级与强化全部归零。

检索练习

先不要往上翻。

1. 为什么购买结果使用枚举？

只返回 bool 会把余额不足、满级和配置错误混成同一种失败。

2. TryPurchase 在哪一步修改金币？

失败交易必须在进入修改阶段前返回。

3. 为什么保存强化等级而不是最终生命值？

场景重建应恢复满资源，再叠加购买等级；旧伤害值不应跨关携带。

4. UpgradeShop 为何在 Awake 注册按钮？

Awake 在首次激活时执行；隐藏顺序不应使按钮监听丢失。

报错急救

现象处理
金币不足仍能点Refresh 是否检查 Coins；TryPurchase 是否仍先验证余额。
失败却扣了金币Coins 修改是否发生在所有 return 之后。
满级仍能点GetLevel 与 MaxLevel 的比较是否在扣费前。
购买后 HUD 不更新PlayerProgress.Changed 是否转发到 PlayerStats.StatsChanged。
下一关没有强化PlayerStats.Awake 是否读取 GameSession.Progress。
补给站按钮无响应UpgradeShop 是否被父级隐藏后才执行 Start；初始化应在 Awake。
