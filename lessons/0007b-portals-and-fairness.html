色彩迷宫 · 开发实训 / 课程 07b

未知
但不该不公平

紫色传送门一开始不告诉玩家对应关系，这是探索的一部分；但未知不能变成随机惩罚。今天做成对传送、首次使用后记忆标记和明确的失败路径。

50–70 分钟 配对 · 查找 · 公平性 产出：可记忆的成对传送门

本课胜利条件

公平性设计

“玩家不知道对应关系”本身没有问题，问题在于未知是否会造成不可预测的惩罚。我们的规则是：

  • 所有传送门初始都是同一种紫色，玩家不知道谁和谁成对。
  • 配对是固定的，不是每次进入随机换出口。
  • 首次使用后，两端变成更亮的紫色，作为“已记住”的视觉提示。
  • 如果地图数据缺少配对，玩家停在原地并收到警告，不扣生命或氧气。
  • 每对传送门必须恰好有两个端点，且放在安全格上。
未知 ≠ 随机惩罚

探索的乐趣来自“观察和记忆”，不是来自“踩错就掉血”。这条边界要在原型阶段明确，否则很难判断玩家是在解谜还是在赌运气。

01

增加 Portal 类型与编号

TileType.cs：

TileType.cs
public enum TileType
{
    Floor,
    Wall,
    Lava,
    Water,
    Stone,
    Chest,
    Portal
}

LevelDefinition.GetTileType 把数字识别成 Portal：

LevelDefinition.cs
char tile = GetTile(cell);

if (tile >= '1' && tile <= '9')
{
    return TileType.Portal;
}

再增加一个查询配对编号的方法。字符 '1' 减去 '0' 会得到整数 1：

LevelDefinition.cs · GetPortalId
public int GetPortalId(Vector2Int cell)
{
    char tile = GetTile(cell);

    return tile >= '1' && tile <= '9'
        ? tile - '0'
        : 0;
}

所有数字显示成同一种紫色；编号只存在于数据里，所以玩家一开始看不出配对关系。

02

Maze 保存编号并查找出口

在 MazeBootstrapper 里增加：

MazeBootstrapper.cs · 数据
using System.Collections.Generic;

private int[,] _portalIds;
private readonly HashSet<int> _knownPortalIds =
    new HashSet<int>();

Start 分配数组时，同时复制编号：

MazeBootstrapper.cs · Start
_portalIds = new int[Width, Height];

Vector2Int cell = new Vector2Int(x, y);
int portalId = level.GetPortalId(cell);
_portalIds[x, y] = portalId;

if (tile == TileType.Portal)
{
    _renderers[x, y].color = PortalColor(portalId);
}

再给 Maze 增加一个查询编号的方法：

MazeBootstrapper.cs · GetPortalId
public int GetPortalId(Vector2Int cell)
{
    if (level == null || _portalIds == null ||
        !level.Contains(cell))
    {
        return 0;
    }

    return _portalIds[cell.x, cell.y];
}

查找另一端：

MazeBootstrapper.cs · TryGetPortalExit
public bool TryGetPortalExit(
    Vector2Int entry,
    out Vector2Int exit)
{
    exit = entry;
    int id = GetPortalId(entry);

    if (id == 0)
    {
        return false;
    }

    for (int y = 0; y < Height; y++)
    {
        for (int x = 0; x < Width; x++)
        {
            if (_portalIds[x, y] != id ||
                (x == entry.x && y == entry.y))
            {
                continue;
            }

            exit = new Vector2Int(x, y);
            return true;
        }
    }

    return false;
}

首次使用后标记整对已知：

MazeBootstrapper.cs · 记忆标记
public void MarkPortalPairKnown(int id)
{
    if (id == 0)
    {
        return;
    }

    _knownPortalIds.Add(id);

    for (int y = 0; y < Height; y++)
    {
        for (int x = 0; x < Width; x++)
        {
            if (_portalIds[x, y] == id)
            {
                _renderers[x, y].color = PortalColor(id);
            }
        }
    }
}

private Color PortalColor(int id)
{
    return _knownPortalIds.Contains(id)
        ? new Color(0.78f, 0.55f, 0.95f)
        : new Color(0.52f, 0.22f, 0.72f);
}

完整文件见 solutions/0008/MazeBootstrapper.cs。7×7 地图直接扫描很便宜；等关卡大很多，再考虑用字典预计算配对。

03

玩家进入传送门后换位置

在 PlayerGridMover.TryMove 更新位置之后、处理宝箱之前加入：

PlayerGridMover.cs · TryMove
if (maze.GetTileType(currentCell) == TileType.Portal)
{
    TryTeleport();
    return;
}

新增传送方法：

PlayerGridMover.cs · TryTeleport
private void TryTeleport()
{
    Vector2Int entry = currentCell;

    if (!maze.TryGetPortalExit(entry, out Vector2Int exit))
    {
        Debug.LogWarning("传送门没有配对的出口。");
        stats.ApplyTile(TileType.Floor);
        return;
    }

    currentCell = exit;
    transform.position = maze.CellToWorld(currentCell);
    maze.MarkPortalPairKnown(maze.GetPortalId(currentCell));
    stats.ApplyTile(TileType.Floor);
    Debug.Log($"传送门: ({entry.x},{entry.y}) ↔ ({exit.x},{exit.y})");
}

传送只在“进入传送门格”时触发；到了出口后不会自动再次触发，所以不会无限循环。出口按地板处理，不额外扣资源。

04

测试公平性

  1. 从起点按 W、W，进入 (1,3)：应该出现在 (5,3)。
  2. 观察两个传送门从深紫色变成亮紫色，表示这一对已经被记住。
  3. 走回另一个传送门，再次进入：仍然到同一个出口，关系固定。
  4. 临时把其中一个 1 改成 .，进入剩下的传送门：玩家停在原地，Console 警告，不扣生命或氧气。
  5. 把地图改回两个 1，再 Play，确认正常。
数据规则

每对编号必须恰好出现两次；只使用 1–9；出口放在安全格。以后做关卡验收清单时，把这些检查写成工具或测试。

检索练习：合上资料再答

先不要往上翻。答错没关系，努力回忆本身就在加固记忆。

1. 为什么所有传送门初始都用紫色？

同色让玩家一开始不知道配对；编号只在数据里，探索后再通过记忆标记揭示。

2. 首次使用后，如何帮助玩家记忆？

首次使用后，整对传送门变成亮紫色，提供可观察、可记忆的反馈。

3. 传送门没有配对出口时应该怎样？

数据错误不应该变成玩家惩罚；停留、警告并保持资源不变，便于开发者修正关卡。

4. 为什么用编号而不是只靠颜色配对？

如果所有传送门都是紫色，需要编号区分不同配对；颜色负责表现，编号负责数据关系。

报错急救

现象最可能原因处理
传送门是洋红色ColorFor 没有 Portal 分支加入紫色，并确认数字映射。
进入后不动没有同编号的第二个端点同一编号必须恰好出现两次。
传送到墙里配对端点的地图数据不对把两个数字放在安全可走格。
重复传送传送后又递归调用移动只在进入时触发一次，不再次调用 TryMove。
颜色不变没有调用 MarkPortalPairKnown传送成功后标记整对编号。
扣血或耗氧把传送门当成危险格，或缺少配对时惩罚传送出口按 Floor 处理，缺失时只警告。
