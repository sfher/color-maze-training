让方块在网格上
走一步

第一屏已经能显示颜色规则，但还不能玩。今天只做一件事：一个黄色方块每次按键移动一格，撞墙停下。

45–60 分钟 C# · Input System · 网格 产出：可移动的玩家

本课胜利条件

先预测：谁来决定“能不能走”

按下 W 时，玩家脚本应该自己判断前面是不是墙，还是去问迷宫？先停三秒，想一个答案再往下看。

如果玩家自己保存一份地图，那么地图一改，玩家和迷宫就会各有一份“真相”，迟早对不上。更稳的分工是：玩家只负责“想走”，迷宫负责回答“这里能不能走”。

本课的分工

Player 负责想走，Maze 负责哪里能走，Transform 负责显示在哪。

Input

读取输入

Keyboard.current 告诉我们这一帧有没有按下 W/A/S/D 或方向键。

Rule

查询规则

MazeBootstrapper.IsWalkable 回答目标格子是不是墙、有没有越界。

Presentation

更新显示

CellToWorld 把格子坐标换成世界坐标，再写入 transform.position。

01

给 Maze 增加两个公开方法

打开 Assets/Scripts/MazeBootstrapper.cs。在 Start() 后面加入下面四个方法。前两个给玩家用，后两个是本文件内部的辅助方法。

MazeBootstrapper.cs · 新增方法
public bool IsWalkable(Vector2Int cell)
{
    if (cell.x < 0 || cell.x >= Width ||
        cell.y < 0 || cell.y >= Height)
    {
        return false;
    }

    return TileAt(cell) != '#';
}

public Vector3 CellToWorld(Vector2Int cell)
{
    return transform.TransformPoint(CellToLocal(cell));
}

private char TileAt(Vector2Int cell)
{
    int index = (Height - 1 - cell.y) * Width + cell.x;
    return MazeMap[index];
}

private Vector3 CellToLocal(Vector2Int cell)
{
    return new Vector3(
        cell.x - (Width - 1) * 0.5f,
        cell.y - (Height - 1) * 0.5f,
        0f);
}

然后把 CreateCell 里计算世界坐标的三行，替换成一次本地坐标赋值：

CreateCell 中的坐标写法
// 替换前
cell.transform.position = new Vector3(
    x - (Width - 1) * 0.5f,
    y - (Height - 1) * 0.5f,
    0f);

// 替换后
cell.transform.localPosition = CellToLocal(new Vector2Int(x, y));

这样格子生成和玩家定位使用同一个坐标公式，不会各算各的。IsWalkable 目前只把 # 当墙；岩浆和水暂时可以走，规则会在后面几课逐步加进来。

为什么先查边界

TileAt 用索引访问字符串，坐标越界会直接抛异常。先在 IsWalkable 里挡住非法坐标，后面的索引才是安全的。这是“先验证，再使用”的常见工程习惯。

02

写 PlayerGridMover.cs

在 Unity 的 Project 窗口右键 Assets/Scripts，选择 Create → C# Script，命名为 PlayerGridMover。双击打开，替换为：

PlayerGridMover.cs
using UnityEngine;
using UnityEngine.InputSystem;

public class PlayerGridMover : MonoBehaviour
{
    [SerializeField] private MazeBootstrapper maze;
    [SerializeField] private Vector2Int startCell = new Vector2Int(1, 1);

    private Vector2Int currentCell;

    private void Start()
    {
        if (maze == null)
        {
            Debug.LogError(
                "PlayerGridMover: 请在 Inspector 里把 Maze 引用拖进来。",
                this);
            enabled = false;
            return;
        }

        currentCell = startCell;
        transform.position = maze.CellToWorld(currentCell);
    }

    private void Update()
    {
        Vector2Int direction = ReadDirection();

        if (direction != Vector2Int.zero)
        {
            TryMove(direction);
        }
    }

    private Vector2Int ReadDirection()
    {
        Keyboard keyboard = Keyboard.current;

        if (keyboard == null)
        {
            return Vector2Int.zero;
        }

        if (keyboard.wKey.wasPressedThisFrame ||
            keyboard.upArrowKey.wasPressedThisFrame)
        {
            return Vector2Int.up;
        }

        if (keyboard.sKey.wasPressedThisFrame ||
            keyboard.downArrowKey.wasPressedThisFrame)
        {
            return Vector2Int.down;
        }

        if (keyboard.aKey.wasPressedThisFrame ||
            keyboard.leftArrowKey.wasPressedThisFrame)
        {
            return Vector2Int.left;
        }

        if (keyboard.dKey.wasPressedThisFrame ||
            keyboard.rightArrowKey.wasPressedThisFrame)
        {
            return Vector2Int.right;
        }

        return Vector2Int.zero;
    }

    private void TryMove(Vector2Int direction)
    {
        Vector2Int targetCell = currentCell + direction;

        if (!maze.IsWalkable(targetCell))
        {
            return;
        }

        currentCell = targetCell;
        transform.position = maze.CellToWorld(currentCell);
    }
}

你的工程已经启用新 Input System，所以这里直接用 Keyboard.current。如果以后要做按键重绑定，再把输入搬到 Input Actions；原型阶段不必提前复杂化。

03

在场景里创建 Player

  1. 菜单 GameObject → 2D Object → Sprites → Square，把新对象命名为 Player。
  2. 在 Sprite Renderer 里把 Color 调成醒目的黄色，例如 RGB (1.0, 0.78, 0.16)。
  3. 把 Transform 的 Scale 设为 (0.8, 0.8, 1)，这样能看到它下面的格子。
  4. 把 Sprite Renderer 的 Sorting Order 设为 10，避免被地板盖住。
  5. 给 Player 添加 PlayerGridMover 组件。
  6. 把场景里挂了 MazeBootstrapper 脚本的对象拖到 Maze 字段。注意拖的是有脚本的那个对象，不是外层空对象 Maze。
  7. 确认 Start Cell 是 (1, 1)。
Inspector 里的引用

[SerializeField] private MazeBootstrapper maze; 的意思是“这个字段是私有的，但请把它显示在 Inspector 里”。如果 Maze 字段显示 None，运行后就会报 NullReferenceException，所以先把引用拖好。

04

Play，然后只走一步

点击 Game 视图让它获得焦点，按 W/A/S/D 或方向键。预期行为：

  • 每按一次键，玩家移动一个格子；按住不放不会连续冲出去。
  • 向左或向上撞到黑色外墙时，玩家停在原地。
  • 岩浆和水目前仍可走，因为规则还没实现。

建议测试顺序：从 (1,1) 连续按两次 W，玩家应到 (1,3)；再按 A，应该被左侧墙挡住；再按两次 D，应到 (3,3)。

为什么用 wasPressedThisFrame

wasPressedThisFrame 只在按下的那一帧为真，所以一次按键只产生一步。若用 isPressed，按住期间每帧都触发，玩家会像滑行一样连续移动。网格游戏通常要的是前者。

读懂这几行

  • Update() 每帧执行，但 ReadDirection() 在没有新按键时返回 Vector2Int.zero，所以不会移动。
  • Vector2Int 存的是整数格子坐标；Vector3 是世界空间位置。两者不要混用。
  • targetCell = currentCell + direction 先算出“想去哪”，再问 IsWalkable；只有答案是可走，才更新 currentCell。这叫“先验证，再提交”。
  • CellToWorld 用 transform.TransformPoint，所以以后移动或缩放 Maze 根对象，玩家仍然会对齐格子。
  • 不要用方块颜色来判断规则。颜色是表现，地图字符才是数据；以后岩浆、水、灰石的规则都应该加在数据/规则层。

检索练习：合上资料再答

先不要往上翻。答错没关系，努力回忆本身就在加固记忆。

1. Update() 最适合承担下面哪件事？

Update 每帧调用，适合读取输入、更新表现；对象初始化通常放 Start 或 Awake。

2. Vector2Int 最适合表示什么？

网格坐标是整数，用 Vector2Int 可以避免浮点误差；世界位置用 Vector3。

3. wasPressedThisFrame 的作用是？

它只在按下的那一帧为真，适合“一次按键走一格”的离散移动。

4. 为什么先调用 IsWalkable 再改 currentCell？

先验证目标格，再提交状态，才能保证逻辑坐标不会进入墙或越界位置。
