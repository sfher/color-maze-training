一键检查关卡

你已经能制作新关卡，现在给内容生产加一条自动验收线：扫描所有 LevelDefinition，检查材料阈值、出口、起点、地图边界和传送门配对。

30–45 分钟 UnityEditor · Validation 产出：关卡校验菜单

本课胜利条件

工具检查“内容合同”

一关要能被游戏可靠加载，至少满足：

START

起点可通行

默认起点 `(1,1)` 不能是墙或灰石。

GOAL

目标完整

材料数不少于所需数量，且恰好一个出口。

EDGE

矩形边界

地图行列本身限制范围，不要求外围墙。

PAIR

传送门成对

每个编号恰好出现两次，避免单向传送。

02

扫描所有关卡资产

LevelValidator.cs
[MenuItem("Color Maze/Levels/Validate All")]
private static void ValidateAllLevels()
{
    string[] guids =
        AssetDatabase.FindAssets("t:LevelDefinition");

    foreach (string guid in guids)
    {
        string path =
            AssetDatabase.GUIDToAssetPath(guid);
        LevelDefinition level =
            AssetDatabase.LoadAssetAtPath<
                LevelDefinition>(path);

        // 检查这个关卡
    }
}

按类型查找比遍历固定文件夹更可靠：关卡以后放在 Data、Content/Levels 或其他目录，都能被发现。

03

统计关键格子

使用 LevelDefinition 已有的公开方法，不直接读取私有 rows：

LevelValidator.cs · 核心检查
TileType tile =
    level.GetTileType(new Vector2Int(x, y));

if (tile == TileType.Material)
    materials++;
else if (tile == TileType.Exit)
    exits++;
else if (tile == TileType.Portal)
{
    int id = level.GetPortalId(cell);
    portals.TryGetValue(id, out int count);
    portals[id] = count + 1;
}

int requiredMaterials = 1;
// 过渡实现使用 1；接口落地后读取
// level.RequiredMaterials。

if (materials < requiredMaterials)
{ /* 报警 */ }

if (exits != 1) { /* 报警 */ }

最后遍历传送门字典，要求每个 ID 的计数恰好为 2。目标规则允许地图中的 `M` 多于所需数量；只有少于阈值才是错误。当前尚未实现 `requiredMaterials`，所以本课暂时仍用 1，而现有关卡要等迁移后才应放入多余材料。

04

让失败信息能定位

不要只打印“关卡错误”。警告应包含资产路径和具体原因：

Debug.LogWarning(
    $"关卡校验失败：{path}\n" +
    string.Join("\n", errors),
    level);

点击 Console 时，context 会自动定位到对应的 LevelDefinition。完成参考：LevelValidator.cs.

05

用一个坏关卡证明工具有效

  1. 运行 Color Maze → Levels → Validate All，现有关卡应通过。
  2. 复制一个关卡资产，删掉出口、让材料数少于所需数量，或把某个传送门改成不同编号。
  3. 再次运行校验，确认 Console 指出具体资产和问题。
  4. 修复后把它加入你的内容目录。
