存档与设置

只序列化数据 DTO；正式档、临时档和备份分开；设置先应用，再由玩家操作写回。

打印友好 JSON · IO · Settings

文件位置

Application.persistentDataPath
  save.json
  save.tmp
  save.backup.json

不要写入 Assets、Unity 安装目录或当前工作目录。

版本

[Serializable]
public class GameSaveData
{
    public int version = 1;
    public int coins;
    public string[] unlockedContentIds;
    public float masterVolume;
}

读取时检查版本；升级字段时迁移旧版本。

保存顺序

  1. JSON 写入 save.tmp。
  2. 完整写入后替换 save.json。
  3. 替换时保留 save.backup.json。
  4. 首次保存直接移动临时文件。

读取顺序

正式档
  ↓ 失败
备份
  ↓ 失败
默认 GameSaveData

坏档要捕获异常，不要自动覆盖，方便定位。

设置应用

AudioListener.volume =
    Mathf.Clamp01(masterVolume);

Screen.SetResolution(
    width,
    height,
    fullscreen);

UI 初始化使用 SetWithoutNotify，避免加载时触发保存。

UI 绑定位置

GameManager
  SettingsController
  SaveCoordinator

Canvas / GameUI
  PausePanel / SettingsButton
  SettingsPanel / Slider
  SettingsPanel / Toggle
  SettingsPanel / Dropdown

控制器挂常驻对象；面板初始化时可关闭，但引用仍能保存。

数据归属

  • 金币、已解锁内容 ID：游戏进度。
  • 当前关卡 ID：游戏进度。
  • 音量、窗口模式、分辨率：玩家设置。
  • 场景对象引用：不要写进 JSON。

必测

  • 正常保存并重进 Play 后恢复。
  • 正式档损坏时读取备份。
  • 两份都缺失时使用默认值。
  • 分辨率不在当前列表中时不越界。

报错急救

读到空对象
JSON 语法错误或 DTO 字段不匹配；先看异常。
设置被重置
先创建默认数据，后应用存档，顺序反了。
加载时自动保存
UI SetValue 触发了 Changed；改用 SetWithoutNotify。
只在编辑器可见
把文件误写到了 Assets，而非 persistentDataPath。
