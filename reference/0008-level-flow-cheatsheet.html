关卡流程与状态

资源、地块、移动各管一件事；关卡进行中、完成、失败由流程控制器统一管理。

打印友好 状态机 目标与出口

三种状态

状态条件行为
Playing关卡开始允许移动与交互
Completed材料数达到关卡阈值并进入出口停止移动，按 R 重开
Failed生命归零停止移动，按 R 重开

职责边界

PlayerStats:
  Health / Oxygen / Bombs
  Coins / Materials

MazeBootstrapper:
  TileType[,]
  Portal IDs

PlayerGridMover:
  currentCell / facing

LevelFlowController:
  Playing / Completed / Failed

不要把“是否过关”塞进 PlayerStats；它只保存资源。

材料

case 'M': return TileType.Material;
case 'E': return TileType.Exit;

public bool HasEnoughMaterial(int required)
    => Materials >= required;

TryCollectMaterial(cell)
  → Material 变 Floor
  → Materials + 1

每拾取一份材料，计数加 1。目标规则允许地图中的材料数多于所需数量；`requiredMaterials` 是预留接口，当前课程示例暂时按 1 比较。

出口检查

if (tile == TileType.Exit)
{
    stats.ApplyTile(TileType.Floor);
    flow.ReachExit(
        stats.HasEnoughMaterial(requiredMaterials));
    return;
}

材料未达阈值时只提示；达到阈值后才进入 Completed。出口本身不是危险格。

阻止继续移动

if (!stats.IsAlive || !flow.IsPlaying)
{
    return;
}

完成或失败后，移动脚本不再响应键盘；这是流程状态对输入层的约束。

状态转换

Playing
  ├─ 材料达标 + Exit → Completed
  ├─ Health == 0   → Failed
  └─ 材料未达标 + Exit → 提示，仍 Playing

材料未达阈值不是失败，也不是完成；玩家应该能继续探索。

测试清单

  • 材料未达阈值到出口：提示，仍可移动。
  • 材料达到阈值后到出口：完成，停止移动。
  • 生命为 0：失败，停止移动。
  • 完成或失败后按 R：重载场景。
  • 重开后资源、材料、位置重置。
  • 没有两层失败/完成覆盖。

报错急救

材料变洋红
ColorFor 缺少 Material，或 M 没映射。
出口没反应
PlayerGridMover 的 Flow 引用为空。
完成后能动
Update 没有检查 flow.IsPlaying。
两层覆盖
GameOverController 与 LevelFlowController 同时挂着。
R 无效
Main 不在构建场景列表，或 Game 视图没焦点。
