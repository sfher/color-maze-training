传送门与公平性

所有传送门同色，编号只存在于数据里；第一次使用后整对变色，让玩家靠观察和记忆，而不是靠随机惩罚。

打印友好 配对 公平性

数据模型

地图字符 1–9 → Portal
字符值 - '0' → 配对编号

All portals: 同一种紫色
Known pair: 更亮的紫色

颜色只负责表现；数字负责配对。这样以后可以在同一关放多对传送门。

配对规则

  • 每个编号恰好出现两次。
  • 两个端点都放在安全可走格。
  • 配对固定，不因每次进入而随机换出口。
  • 没有配对时停留并警告，不惩罚玩家。
  • 首次使用后标记整对已知。

查找出口

int id = GetPortalId(entry);

for each cell:
    if id matches and cell != entry:
        exit = cell;
        return true;

return false;

7×7 地图直接扫描足够便宜；大关卡再考虑用字典预计算。

记忆标记

private readonly HashSet<int>
    _knownPortalIds = new HashSet<int>();

_knownPortalIds.Add(id);
// 重新给同编号的两端上色

HashSet 只关心“这个编号是否已经记住”，适合唯一标记。

传送顺序

1. 进入 Portal 格
2. 查找同编号出口
3. currentCell = exit
4. transform.position = CellToWorld(exit)
5. 标记整对已知
6. 按 Floor 应用效果

只在“进入”时触发一次，不递归调用移动，避免无限传送。

测试清单

  • 两端初始深紫色，配对未知。
  • 进入一端后到达另一端。
  • 首次使用后两端变亮紫色。
  • 再次进入仍然到同一出口。
  • 缺少一端时停留并警告。
  • 传送不扣生命或氧气。

报错急救

传送不动
同编号没有第二个端点，或编号查询为 0。
传到墙里
端点地图数据不对；先把两个数字放在安全格。
无限传送
出口后又递归调用 TryMove；只触发一次。
颜色亮错
已知编号和实际所在编号不一致。
随机惩罚
缺配对或出口危险；未知不能用随机扣资源处理。

可选数据校验

在 LevelDefinition.OnValidate 统计每个数字出现次数：

  • 次数为 0：忽略。
  • 次数为 2：正常。
  • 其他次数：Console 警告并列出编号。

这是关卡验收工具，不是玩家运行时逻辑。
