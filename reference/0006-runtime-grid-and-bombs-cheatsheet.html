运行时地图与炸弹

关卡资产是模板，运行时副本才是这一局的状态。炸石头要同时改逻辑格子和画面，并且只在确认目标合法后消耗炸弹。

打印友好 二维数组 资源消耗
历史规则

当前炸弹不是瞬间炸前方：按 E 原地放置，三次有效移动后爆炸，破坏上下左右灰石并可伤到玩家。请以项目内 docs/LEVEL_DESIGN_GUIDE.md 为准。

模板 → 运行时

LevelDefinition（资产）
  rows: "#######", ...
        ↓ Start 时复制
TileType[,] _tiles（这一局）
        ↓ 炸石头
_tiles[x, y] = Floor
_renderers[x, y].color = 地板色

不要写回 LevelDefinition；否则停止 Play 后模板可能被永久修改。

Stone 类型

public enum TileType
{
    Floor,
    Wall,
    Lava,
    Water,
    Stone
}

地图字符 S → TileType.Stone；未知字符仍默认 Wall。

二维数组

private TileType[,] _tiles;

_tiles = new TileType[Width, Height];

_tiles[x, y] = tile;
TileType tile = _tiles[cell.x, cell.y];

第一维是 x，第二维是 y；数组下标从 0 开始，访问前先检查边界。

破坏石头的顺序

1. 前方目标是不是 Stone？
2. 玩家还有炸弹吗？
3. 扣炸弹
4. _tiles[cell] = Floor
5. _renderers[cell].color = ColorFor(Floor)

目标不合法就不消耗资源；逻辑与显示必须同步更新。

面朝方向

private Vector2Int facing = Vector2Int.up;

// 每次尝试移动先记录方向
facing = direction;

// 炸弹作用于前方一格
Vector2Int target = currentCell + facing;

撞墙也算“面朝该方向”；这样玩家可以先按方向键对准石头，再按 E。

炸弹资源

public int Bombs { get; private set; } = 1;

public bool TryConsumeBomb()
{
    if (Bombs <= 0)
        return false;

    Bombs -= 1;
    return true;
}

返回 bool 让调用方知道是否真的消耗成功；不要先减到负数再判断。

测试清单

  • 石头挡住 Movement。
  • 朝石头按 E：石头变地板，炸弹 1 → 0。
  • 炸开后能走进原石头格。
  • 没有石头时按 E：不扣炸弹。
  • 停止 Play 后资产里的 S 还在。
  • 再次 Play，石头重新出现。

报错急救

洋红色
ColorFor 缺少 Stone，或 S 没映射。
炸不开
朝向不对，或 TryBreakStone 没有改 _tiles。
扣了炸弹
先消耗后验证；应先检查目标是否 Stone。
石头永久消失
写回了 LevelDefinition 资产，而不是运行时副本。
画面没变
只改了 _tiles，没有改对应 SpriteRenderer 颜色。
