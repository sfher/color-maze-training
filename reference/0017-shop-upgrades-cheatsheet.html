金币与购买校验

强化内容是资产，金币与等级是运行进度，购买是一次会返回明确结果的交易。三者分开，UI 才能准确显示“为什么买不了”。

运行进度

PlayerProgress
  Coins
  Dictionary<UpgradeType, int>
  event Action Changed

只存余额和强化等级，不存上一关受伤后的生命与氧气。

交易顺序

  1. Upgrade 是否为空？
  2. 是否已经满级？
  3. Coins 是否足够？
  4. 扣除 Coins。
  5. 等级 +1。
  6. 发布 Changed。

所有失败返回必须发生在扣费之前。

TryPurchase

if (Coins < cost)
    return PurchaseResult.NotEnoughCoins;

Coins -= cost;
_levels[upgrade.Type] = level + 1;
Changed?.Invoke();
return PurchaseResult.Purchased;

成功路径只有一条，余额和等级一起变化。

商店刷新

cost = definition.CostFor(level);
label = name + level + cost;
button.interactable =
    level < maxLevel
    && Coins >= cost;

按钮禁用只是提示，模型里的 TryPurchase 仍是最终校验。

生命周期

  • UpgradeShop 在 Awake 注册行按钮。
  • GameHud 可能在 Start 立即隐藏面板。
  • 隐藏不能导致按钮监听永远未注册。
  • OnDestroy 移除相同监听。

持久范围

  • 同一次 Play：金币与强化跨场景保留。
  • 停止 Play：PlayerProgress 重建。
  • 文件存档：课程 13。

报错急救

出现负金币
余额修改发生在验证之前。
满级仍扣钱
MaxLevel 检查缺失或顺序错误。
下一关丢失
PlayerStats 没读取 GameSession.Progress。
商店按钮无响应
Start 因对象被隐藏而未执行，改在 Awake 注册。
