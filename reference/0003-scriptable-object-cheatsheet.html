ScriptableObject 与关卡数据

把“内容”从“行为”里拆出来。关卡、道具表、数值配置适合做成资产；玩家的当前生命值、当前格子不适合。

打印友好 数据资产 编辑器 vs 运行时

MonoBehaviour vs ScriptableObject

MonoBehaviourScriptableObject
挂载位置场景里的 GameObjectProject 里的资产
适合行为、输入、渲染、碰撞关卡、道具表、数值
生命周期随场景加载/销毁作为资产被引用
运行时状态适合不适合保存玩家进度

最小模板

[CreateAssetMenu(
    menuName = "Color Maze/Level Definition",
    fileName = "Level_01")]
public class LevelDefinition : ScriptableObject
{
    [SerializeField] private string[] rows;
}

[CreateAssetMenu] 负责在 Create 菜单里加入口；[SerializeField] 负责让私有字段出现在 Inspector。

关卡查询 API

public int Width  => rows[0].Length;
public int Height => rows.Length;

public bool Contains(Vector2Int cell)
{
    return cell.x >= 0 && cell.x < Width &&
           cell.y >= 0 && cell.y < Height;
}

public char GetTile(Vector2Int cell)
{
    int row = Height - 1 - cell.y;
    return rows[row][cell.x];
}

调用 GetTile 前先用 Contains 检查边界；不要依赖调用方永远传对坐标。

数据校验

private void OnValidate()
{
    if (rows == null || rows.Length == 0)
        return;

    int width = rows[0].Length;

    for (int i = 0; i < rows.Length; i++)
    {
        if (rows[i].Length != width)
            Debug.LogWarning(
                $"第 {i + 1} 行长度不一致", this);
    }
}

OnValidate 在编辑器里修改资产时运行，适合做“数据形状”检查；它不是运行时业务逻辑。

地图坐标

rows[0] 是最上面一行，而 Unity 的 y 轴向上。因此：

int row = Height - 1 - cell.y;
char tile = rows[row][cell.x];

如果地图上下颠倒，先检查这一行。宽高从数据推导，不要在多个地方写死 7。

运行时 vs 编辑器

UnityEngine
运行时程序集，玩家构建里存在；MonoBehaviour、SpriteRenderer、Vector2Int 都在这里。
UnityEditor
只在编辑器里存在；打包后的玩家构建没有它。运行时脚本不要 using UnityEditor。
Editor/
放在名为 Editor 的目录里的脚本只在编辑器编译，适合自定义 Inspector、菜单工具。
#if UNITY_EDITOR
需要把少量编辑器代码和运行时脚本放在同一文件时，用条件编译隔离。

什么时候该拆数据

  • 同一份逻辑要服务多个关卡、道具或角色。
  • 内容会频繁调整，但代码逻辑稳定。
  • 希望非程序员也能编辑内容。
  • 数据需要被多个场景或系统共享。

只有一关时也可以先写死；但一旦出现“复制脚本改地图”的冲动，就是拆数据的信号。

报错急救

Create 没入口
脚本编译失败，或类名/文件名不一致；先看 Console。
Level 是 None
资产没有拖到 MazeBootstrapper 的 Level 字段。
全洋红
地图里有未识别字符；只允许 # . R B。
索引越界
某一行长度不一致，或调用 GetTile 前没检查 Contains。
打包失败
运行时脚本引用了 UnityEditor；删掉或移到 Editor 目录。
